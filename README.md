# SimSim 0.8.0-dev — タスク・挙動・記録再生

静的HTTP／HTTPSサーバで動く、ミッション設計とモンテカルロ比較のための試作アプリです。HTML・CSS・JavaScriptと同梱のThree.jsだけで動作し、動的サーバ、外部CDN、外部APIは不要です。

開発ブランチ: `feat/shared-behavior-replay`。GitHub Pages: https://zero-error-no-warning.github.io/SimSim/ 。社内ポータルでは、このブランチの **Code → Download ZIP** を展開し、ファイル一式を同じ構成で静的HTTPサーバに置いてください。JavaScriptモジュールをJavaScriptのMIMEタイプで配信する必要があります。データはJSON内容の `.jsn` です。`file:` 起動には対応しません。

## 最初の操作

1. 起動時の「島間通過・周回UUV」サンプルで **計算** を押す。
2. 完了後、**再生** または時刻スライダーで経過を確認する。時刻移動による再計算は行いません。
3. 地図か左の一覧でユニットを選ぶ。右には基本属性と担当タスクが表示され、経路・センサー・通信などは必要な欄を開いて編集する。
4. 左のタスクを選ぶ。「担当・経路」で担当する単体／群、共有経路、出発割合などを設定する。「挙動のノード」で条件付きの動作を編集する。
5. **分析** でUUV数×探知距離を比較する。横軸は数値に合わせた散布図で、線形／対数を選べます。表の **再現** で一つの試行を計算・記録する。
6. **保存** はシナリオ定義、**記録保存** は計算済みの再生記録を保存する。いずれも上の **開く** から読み込む。

操作・モデル・保存形式・制約は [現在の操作と設計](docs/workspace-v3.md) にまとめています。

起動条件（シーン開始・情報受信・指定時間経過・対象探知）から処理ノードへ接続して挙動を起動します。ホイール拡大縮小・全体表示・ミニマップ移動に対応しています。従来の開始ノード指定は読み込み時にシーン開始の起動条件へ変換します。

ノード編集は「＋追加」でノードを作成してから、クリックして種類を設定します。線も先につなぎ、線をクリックして遷移条件を選びます。種類・条件の選択欄は、選択した要素の編集欄に表示します。

## 0.8で整理したこと

- 旧「行動・通信」画面と旧行動実行系を廃止。通信能力はユニット属性、条件付き動作は挙動ノードへ統合。
- 通常経路、共有タスク、群の個数0、分析、記録再生が同じ実行モデルを使う。
- 地図・経由点・数値欄の経路編集先を共通化。共有経路の編集が古いユニット経路だけを書き換える不整合を修正。
- 新規作成、削除、分析変数の参照を整理。使われない位置・配置変数を共有経路の担当者に提示しない。
- 通信中継で探知対象の情報を保持。同時に届く報告、通信遅延、準備時間、到着時刻を検証。
- 航跡は再生記録から作成し、時刻移動の順序に左右されない。

旧シナリオ定義（version 1/2）は読込時に変換します。変換できない複合ルールは説明付きで拒否します。**旧版の分析結果・再生記録は旧版で開いてください。** モデル変更前の結果を新モデルとして読み替えません。

## 検証と開発

ローカル起動:

```sh
python3 -m http.server 8000
```

http://localhost:8000/ を開きます。計算・編集・保存形式の回帰テスト:

```sh
node --test tests/*.test.mjs
```

ブラウザの統合テストはPlaywrightとChromiumが必要です。静的サーバをテスト内で起動し、外部通信を許可しないCSPで確認します。

```sh
node tests/browser-smoke.mjs
```

Playwrightのモジュール指定は `SIMSIM_PLAYWRIGHT`、Chromiumの実行ファイル指定は `SIMSIM_BROWSER_EXECUTABLE`。通常のアプリ配布にこれらは不要です。検証範囲は [検証](docs/workspace-v3.md#検証) を参照してください。

画面・JavaScriptを更新して公開する前に、`src/ui-dom.js` の `UI_BUILD` を変更し、`node tools/version-assets.mjs` を実行してください。HTML・起動スクリプト・依存モジュール・Workerの読み込みURLを同じ版で更新します。HTMLとJavaScriptの版が混在した場合は起動を止め、画面内に版情報・エラー詳細・最新版の再読込リンクを表示します。画面初期化失敗をWorkerのタイムアウトとして表示しません。

起動不具合の回帰テストは `node tests/startup-browser.mjs`。旧HTMLとの混在、画面部品の欠落、キャッシュされた旧モジュールの回避、実際のWorker無応答、環境確認の本体Workerを検証します。

計算Workerの起動は最大60秒待ち、10秒経過時には起動待ちとして表示します。環境確認v1.3はWorkerを一つずつ確認し、60秒で無応答の場合も非対応と断定せず判定保留とします。診断の旧10秒タイムアウトだけでは、起動遅延と環境制限を区別できません。

本アプリの地形・装備性能・サンプルは架空です。水中探知は距離・確率・直線遮蔽の簡易モデルです。実際のソナー伝搬や装備の必要数を検証したモデルではありません。

依存ライブラリ: Three.js 0.170.0と同版OrbitControlsを固定して同梱。MITライセンスと取得元は `vendor/three/` に収録しています。[環境確認](environment-check/check.html) ではWebGL・Worker・静的データ取得を確認できます。
