# SimSim 0.3

静的HTTP／HTTPSサーバで動作する、ミッションシミュレーションの空間・時間基盤。

## 起動

GitHubの **Code → Download ZIP** から取得し、展開したファイル一式を社内ポータルの同じ配下へ配置して `index.html` を開く。アプリ・ライブラリ・地形データはすべて同梱。サーバ側プログラム、外部CDN、外部APIへのアクセスは不要。

ローカル確認用の例:

```sh
python3 -m http.server 8000
```

`http://localhost:8000/` を開く。HTMLファイルの直接起動（file:）は対象外。

GitHub Pages: `Settings → Pages → Deploy from a branch → main → /(root)`。標準URLは https://zero-error-no-warning.github.io/SimSim/ 。公開設定が有効になっている場合、このURLで利用できる。

## できること

- 架空の島・周辺海域・海底を3Dまたは真上から表示。
- 地上・水上・水中・空中のユニットを追加、編集、削除。
- 初期位置・経由点を地図クリックまたは数値入力で指定。
- 定速移動、一度だけ・往復・周回、再生・一時停止・時刻指定・初期位置へのリセット。
- 地形制約に反する経路は理由を表示して停止。自動経路探索は行わない。
- 群のひな型・個数・配置範囲による生成。ランダム配置／格子配置。単体＋群の上限2000個。
- 航跡の水平・上下のずれ、群に共通する水平のずれ、速度・出発時刻のばらつき。
- 乱数シードと試行番号による再現。「次の試行」で条件を振り直す。
- インスタンス描画。80個を超えると選択中のラベル・経路・航跡と群の個数を表示。
- 計画経路（白破線）と、生成された移動経路（陣営色／選択色）を表示。
- 汎用の球状探知モデル。最大距離、距離0で1分の探知確率、対象領域、被探知係数を設定。
- 地形格子による直線の見通し判定（切り替え可能）。
- 期限までの探知を成功条件に設定。一つ／すべてを選択。
- 群の個数を変えたモンテカルロ、成功率・未成立率・95%信頼区間のグラフと表。
- 成功／失敗した試行の再現、探知履歴、選択センサーの最大範囲の可視化。
- 分析結果を条件ごと`.jsn`で保存・読み込み。
- 25段階のUndo/Redo。
- `.jsn`による保存・復元。読み込みは`.json`も受け付けるが、同梱データ・出力は`.jsn`。
- 航跡、海面、経路、高さ表示倍率の切り替え。

## 操作

1. 左の一覧または地図の記号をクリックしてユニットを選択。
2. 右の設定欄で速度・領域・有人無人・高度または深度を変更。
3. 「地図で初期位置を指定」または「地図で経由点を追加」を押し、地図上をクリック。Escで終了。
4. 「再生」。×60なら1秒の実時間で60秒のシミュレーション時間が進む。
5. 保存すると初期配置・経路・設定を`.jsn`でダウンロードする。現在時刻や航跡は保存せず、読み込み時は時刻0から開始。

ドラッグ: 視点回転。右ドラッグ: 移動。ホイール: 拡大縮小。真上では回転せず平面表示。Space: 再生／一時停止。Ctrl/Cmd+Z: Undo、Ctrl/Cmd+Shift+Z: Redo。

設定を変更すると時刻を0へ戻す。シミュレーションの計算と描画は独立しており、高さ表示倍率は計算に影響しない。

## 群・ばらつきの操作

1. 「1000個の群サンプル」で1000個のUUV群と7個の単体を読み込む（架空の動作確認用）。
2. 左の群ボタンを押し、個数・配置幅・ばらつきを変更。群の属性・経路は保存済みのひな型を維持する。別の単体を選ぶとその定義へ置き換える。
3. 任意の単体を選び「選択ユニットから群を作る」こともできる。元の単体は残り、群のひな型はコピーとして保存する。
4. 「試行設定」を開き、シード・試行番号を変更。「次の試行」で配置、経路、速度、出発遅れを再生成する。
5. 一覧は先頭80個＋選択中まで。名前・IDで検索すると、群の1000番目なども選択できる。生成メンバーは読み取り専用で、群の設定から変更する。

航跡のずれは平面内の全方向に作用する簡易モデル。出発点・最終目的地は固定し、間の経路を滑らかなノイズで変形する。実際の3D経路長に沿って速度一定で進む。往復は同じ経路を逆向きに通り、周回は同じ生成経路を繰り返す。旋回半径・海流の速度場・操縦制御のモデルではない。

群の配置は、ひな型の初期位置を中心とする長方形内のオフセットで経路全体を平行移動する。地形に反した配置・航跡を自動修正／再抽選せず、制約違反として残す。到達可能な区間で停止し、理由を表示する。

## 探知・モンテカルロの操作

1. 地図上の「探知・分析」を開き「架空の探知サンプル」を押す。
2. 「分析を実行」。0／100／300／1000個を各50試行で比較する。0は比較対象の群を取り除く条件。有人の単体はそのまま。
3. 棒が成功率、縦線がWilson法の両側95%信頼区間、橙の線が入力した要求率。表には未成立率と成功試行の成立時刻中央値も表示する。
4. 各行で試行番号を選び「再現」。その個数・試行番号のシナリオへ切り替え、成立時刻または期限を表示する。リセット／再生で経過を確認できる。
5. 「探知履歴」で初回探知の観測側・対象側・時刻を確認。地図には直近3件の接触線、探知済み対象のラベル枠を表示する。
6. 「分析元のシナリオに戻す」で元の定義へ戻る。通常の編集を行うと古い分析結果はクリアする。
7. 「結果を.jsnで保存」で分析元シナリオと各試行結果をまとめて保存。上部の「開く」で復元する。読み込み時の率・区間は試行結果から再集計するが、シミュレーションを再計算した結果ではない。

任意のシナリオでは、単体または群の設定欄の「簡易探知モデル」を設定し、成功条件・比較する群・個数・試行数を入力する。判定間隔が粗いと短い接触を見逃すので、間隔を小さくした場合との比較が必要。

モデルの式・制約・保存形式: [docs/detection-model.md](docs/detection-model.md)。同梱の性能値・配置はすべて架空で、実際の装備の必要数を示すものではない。

形式: [docs/scenario-format.md](docs/scenario-format.md)。環境確認: [environment-check/check.html](environment-check/check.html)。

## 依存ライブラリ

Three.js 0.170.0を固定して同梱。OrbitControlsは同じ版を使用し、import参照のみローカル相対パスに変更。MITライセンス全文と取得元を`vendor/three/`に同梱。

## 検証

純粋な計算モデルの検証:

```sh
node tests/engine.test.mjs
```

ブラウザではWebGL 2・module Worker・静的ファイル取得が必要。追加した乱数・群モデルの検証:

```sh
node tests/random.test.mjs
```

1000個のノイズ付き移動計算と1007個のブラウザ表示・Worker再生を検証。実行環境により速度は異なる。簡易探知モデルでは複数個数×50試行を確認。通信・より複雑なモデルを含む性能は未測定。

検証条件と結果: [docs/validation.md](docs/validation.md)。

探知・集計の検証: `node tests/detection.test.mjs`。
