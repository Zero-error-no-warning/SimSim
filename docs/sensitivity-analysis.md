# 感度分析（UI v2026.10.07.22）

「分析」→「分析の種類」→「感度分析（一項目ずつ変更）」を選ぶ。サンプルの「感度分析：通信・移動・報告周期」で通信成功率、UAV速度、繰り返し報告の周期を試せる。

## 操作

1. ミッションと必要な追加計測点を設定する。
2. 評価指標を選ぶ。ミッションの成立率・成立時刻、各追加計測点の到達率・成立時刻・起点からの所要時間を扱う。
3. 対象を切り替え、調べる性能にチェックを入れる。選択は対象を切り替えても保持する。初期候補は位置・航跡のずれなどを除く性能を最大32項目選ぶ。それらの位置関連の数値も手動で選べる。
4. 現在の基準値を確認し、小さい値・大きい値を編集する。初期値は基準の±10%。0では表示単位の1、整数では最低1の差を使い、範囲端では片側だけ変える。小さい値 ≤ 基準値 ≤ 大きい値とし、少なくとも片側は基準と異なる値にする。
5. 共通の試行数を設定し、実行する。基準は現在のシナリオの数値。全組合せ用の比較値は使わない。
6. 表またはグラフを選ぶ。「対象を表示」でユニット・群・タスクを一覧と3Dで強調する。ノードの数値では該当する状態・イベントをノード図で選択する。
7. 対応する試行を選び、基準・変更をそれぞれ再生して原因を確認する。「分析元のシナリオに戻す」で基準に戻せる。

単体・群の性能、既存のタスク側の数値に加え、挙動の固定数値も選択できる。

| 対象 | parameter | 数値 |
|---|---|---|
| `behavior:<graph-id>` | `behavior.node.<node-id>.seconds` | 時間待ちの秒数。`parameter:"preparation"` はタスクの `behavior.preparation` を使う |
| `behavior:<graph-id>` | `behavior.node.<node-id>.speedFraction` | 周回速度割合、0.05～1 |
| `behavior:<graph-id>` | `behavior.trigger.<trigger-id>.seconds` | 時間イベントの発火秒数。繰り返しの場合は周期として働き、0は不可 |

挙動の固定数値の変更は、その挙動を使用する全タスクに適用される。担当値を参照するノードの数値は固定値の候補に含めない。新しい挙動の数値は通常の比較変数・ばらつきでも使用できる。

## 計算・集計

基準1条件と、各項目の小さい値・大きい値の条件を計算する。基準と同じ側は追加計算しない。1条件で変えるのは一項目だけ。他の設定・シード・試行番号・ばらつきの抽出値を共通にする。感度分析の項目と同じ性能をばらつきでも指定すると、変更値が抽出値に置き換わるため候補から除外する。

到達率・成立率は成功=1、未達=0として全試行を使用する。平均差は変更率−基準率で、画面では百分率の**ポイント差**。基準50%→変更60%なら+10ポイント。

成立時刻・所要時間は、基準と変更の両方で有効な値を持つ**同じ試行番号**だけを使う。各試行の変更時間−基準時間を平均する。表の「対応基準の平均」「対応変更の平均」も同じ対応試行集合の平均。未達を0秒にしない。所要時間は起点・終点が成立し、終点が起点以降の場合だけ有効。複数担当の成立時刻どうしの差で、同じ個体の移動時間とは限らない。

選択した結果の詳細には各条件単独の有効値の平均と件数、初期配置不正を含む対応試行数も表示する。時間の比較では、両方で到達できた試行に限った差になるため、未達件数・到達率も別途確認する。

順位は今回指定した変更幅での平均差の絶対値。項目ごとに両方向の最大を取り、同じ項目の小さい値・大きい値を並べる。計測値がない方向には順位を付けない。0の差も表示する。この順位は全パラメータの普遍的な重要度や複数項目の組合せ効果を表すものではない。

差の95%近似区間は、対応試行の差の不偏標準偏差を√対応数で割った標準誤差に、Student tの95%係数を掛ける。小標本は自由度1～30の係数、大標本は保守的な近似係数（30超～60で2.042、60超～120で2、120超で1.96）。率の差の区間は−1～1に制限する。1対応試行では区間なし。観測した差が全て同じなら幅0になる。特に少数試行やまれな事象では不確実性を十分表せない場合がある。区間は複数項目の同時比較についての補正を行わない。

## 保存と互換性

感度分析設定はシナリオversion 3の `analysis` に追加する。値はSI単位。

```json
{
  "mode": "sensitivity",
  "trials": 100,
  "step": 10,
  "requiredRate": 0.95,
  "factors": [],
  "uncertainties": [],
  "sensitivity": {
    "metric": "mission.rate",
    "candidates": [
      {"target":"unit:relay","parameter":"interaction.communication.probability","low":0,"high":1}
    ]
  }
}
```

`mode` 省略時または `comparison` は従来の全組合せ比較。指標IDは `mission.rate|mission.time` と `point.<measurement-id>.rate|time|duration`。最大32項目、最大65条件、条件数×試行数10000以下。各条件1～2000試行。地形制約、群の個数、挙動・人口の上限も検証する。

「結果を.txtで保存」は `type:"SimSim-sensitivity", version:1, model:"trigger-behavior-v3"` のファイルを作る。元のシナリオと、基準・変更条件の試行結果を保存する。平均差・順位は読み込み時に試行結果から再集計する。試行番号・抽出値・状態到達・追加計測点を検証し、基準のない変更試行は拒否する。

途中中止でも完了済み試行だけを保存・再読込できる。変更条件が未計算の場合は順位を作らない。再開・未完了条件の追加計算は未実装。

従来の `SimSim-analysis` version 5、記録version 2、シナリオversion 3はそのまま使用できる。設定で参照するユニット・挙動・ノード・計測点を削除した場合は関連参照も整理し、Undoで戻せる。
