# SimSim 0.3 シナリオ形式

ファイル拡張子は `.jsn`、内容はUTF-8のJSON。配信サーバで `.json` が禁止されている環境でも利用できる構成。

## 座標と時間

- `unitsSystem: "SI"`。距離m、速度m/s、時間s。
- 局所直交座標: `x` は東、`y` は北、`z` は標高（海面を含む共通基準）。平面モデルで、緯度経度・地球曲率は未実装。
- 表示の高さ倍率は描画だけに適用。速度・距離・地形制約の計算には影響しない。
- `duration`: 終了時刻、0より大きく86400秒以下。

## トップレベル

| フィールド | 定義 |
| --- | --- |
| `version` | 1 |
| `title` | 1～160文字 |
| `notes` | 任意の注記 |
| `unitsSystem` | `SI` |
| `duration` | 秒 |
| `terrain` | 下記の格子地形 |
| `seed` | 任意の乱数シード文字列、100文字以下。既定値 `SimSim` |
| `trial` | 任意の試行番号、0～1000000000の整数。既定値0 |
| `groups` | 任意の群定義配列、最大100件 |
| `mission` | 任意の探知成功条件。[探知モデル仕様](detection-model.md) |
| `analysis` | 任意の個数比較・モンテカルロ設定。[探知モデル仕様](detection-model.md) |
| `units` | 下記の単体ユニット配列（群と合計2000個まで） |

## 地形

| フィールド | 定義 |
| --- | --- |
| `columns`, `rows` | 各2～513の整数 |
| `origin` | 格子の南西端 `{ "x": 数値, "y": 数値 }` |
| `spacing` | 両軸の格子間隔m、1～10000 |
| `seaLevel` | 海面の標高m |
| `elevations` | `columns * rows` 個の標高m、-12000～10000 |

配列インデックスは `row * columns + column`。columnは東へ、rowは北へ増加する。セル内の高さは双線形補間する。

地表種別、海流、道路、建物は初版では扱わない。同梱地形は架空の標高・水深データであり、実地形ではない。

## ユニット

```json
{
  "id": "uuv-1",
  "name": "UUV 01",
  "domain": "subsurface",
  "kind": "uuv",
  "faction": "friendly",
  "manned": false,
  "speed": 3.8888888889,
  "initial": {"x": 1000, "y": -4500, "z": -120},
  "route": [{"x": 6500, "y": -6500, "z": -120}],
  "routeMode": "pingpong",
  "components": []
}
```

| フィールド | 定義 |
| --- | --- |
| `id` | 重複しない英数字・`_`・`-`、1～80文字 |
| `name` | 1～120文字 |
| `domain` | `ground`, `surface`, `subsurface`, `air` |
| `kind` | 任意の分類メタデータ。初版の移動はdomainで決まる |
| `faction` | `friendly`, `hostile`, `neutral` |
| `manned` | 有人true / 無人false |
| `speed` | 定速m/s、0～1500 |
| `initial` | 初期座標 `{x,y,z}` |
| `route` | 経由点の配列、最大500点。initialは含めない |
| `routeMode` | `once`: 終点で停止、`loop`: 終点から初期位置へ戻る、`pingpong`: 同じ経路を逆順に往復 |
| `sensor` | 任意の簡易探知設定。下記仕様参照 |
| `detectability` | 任意の被探知係数、0～10、既定1 |
| `motion` | 任意の航跡・移動ばらつき設定。下記参照 |
| `components` | 将来の能力モデル用。初版では実行しない。内容は保存時に維持する |

未知のメタデータも読み込み・保存時に維持する。編集UIの高度・深度変更は、初期位置とすべての経由点へ同じ高さを設定する。

## 移動と制約

- 地上: 海面より高い地表に沿って移動する。指定zは地形からの高さに置き換える。
- 水上: 海面に沿って移動する。水深5m以上を必要とする。
- 水中: 海面下1m以上、海底から5mより上に配置する。各経由点の深度を補間する。
- 空中: 地表・海面から10mより高くする。各経由点の高度を補間する。

経路は地形格子間隔の1/4または125mの小さい方でサンプリングし、地形制約を調べる。制約違反の直前にある到達可能なサンプル地点で停止し、理由を表示する。粗い地形とサンプリングに基づく近似であり、厳密な海岸線・衝突判定ではない。

地上は地表に沿った近似3D経路長、水上・水中・空中は3D経路長に対して定速で移動する。加減速・旋回半径・航続・燃料・地形回避・通信・交戦は未実装。探知は別モジュールで評価する。

Worker内で任意の時刻を評価できるため、同じ設定・時刻なら描画頻度に依存せず同じ位置が得られる。保存内容はシナリオ定義であり、実行中の時刻・航跡は含まない。


## 群

```json
{
  "id": "uuv-group", "name": "UUV群", "count": 1000,
  "placement": "random", "width": 1000, "height": 1000,
  "template": { "id": "template-uuv", "name": "UUV", "domain": "subsurface",
    "faction": "friendly", "manned": false, "speed": 4,
    "initial": {"x": 1000, "y": -4500, "z": -120},
    "route": [{"x": 6500, "y": -6500, "z": -120}], "routeMode": "pingpong",
    "motion": {"horizontal": 300, "vertical": 15, "commonHorizontal": 100,
      "scale": 2000, "startDelay": 120, "speedVariation": 0.1}
  }
}
```

| フィールド | 定義 |
| --- | --- |
| `id` | 群同士で重複しない英数字・`_`・`-`、1～50文字 |
| `name` | 1～100文字 |
| `count` | 1～2000の整数。単体＋全群の合計2000個まで |
| `placement` | `random`: 一様ランダム、`grid`: 格子セル中心 |
| `width`, `height` | 配置範囲のx・y幅m、0～100000。中心はひな型の初期位置 |
| `template` | ユニットと同じ構造。idは生成時に置き換える |

生成IDは `群id__1`、`群id__2`…で固定する。単体との衝突はエラー。生成メンバーの内部フィールド `groupId` は予約済みで、単体定義には使わない。経路全体に配置オフセットを足す。生成済みメンバーはファイルへ書かず、群とひな型を保存する。単体とひな型は独立したコピー。

ランダム配置では、個数を増減しても既存メンバーの配置・個体ノイズを維持する。格子配置は個数によって行・列数が変わるため既存位置も変わる。格子は列数 `ceil(sqrt(count))`、行数 `ceil(count/列数)`、各セル中心に順に配置する（最後の行は一部空く）。

## 航跡と乱数

| `motion`内のフィールド | 定義・既定値 |
| --- | --- |
| `horizontal` | 個体の水平ずれの最大半径m、0～10000、既定0 |
| `vertical` | 上下ずれの最大絶対値m、0～3000、既定0。水中・空中のみ |
| `commonHorizontal` | 群に共通する水平ずれの最大半径m、0～10000、既定0 |
| `scale` | ノイズの値を更新する経路上の間隔m、10～100000、既定2000 |
| `startDelay` | 出発遅れの上限秒、0～86400、既定0。各個体で一様抽選 |
| `speedVariation` | 基準速度に対する±割合、0～1、既定0。例えば0.1なら±10%以内を一様抽選 |

乱数ストリームは `simsim-rng-v1` の文字列ハッシュで定義する。シード・試行番号・固定ID・用途（配置／個体移動／共通移動）から決まり、描画回数や評価順に依存しない。将来のモデル変更時には再現仕様のバージョンを変更する。同じコード・同じ定義・同じシード・同じ試行番号で再現できる。

経路上の距離に沿って水平ベクトル（単位円内）と上下成分（-1～1）を抽選し、隣接値をsmoothstep補間する。出発点と最終目的地に向けてずれを0にする。個体と共通の水平ずれは加算するので、合計上限は両者の上限の和。`commonHorizontal`は同じ群の同じ経路距離で同じ値を使う。単体ではその個体用の追加ストリームになる。

生成経路を折れ線としてサンプリングし、地形制約を調べて3D累積距離を再計算する。地上・水上のzは地表・海面に投影する。単に表示だけを振る処理ではない。位置ずれは水平の全方向で、横方向だけに限定した航法誤差・実際の流体場・機体の旋回限界は未実装。往復と周回は同じ生成経路を繰り返し、周回ごとの再抽選は行わない。

`evaluate(t)`の各ユニットには `actualSpeed`（今回のm/s）、`startDelay`（今回の秒）を含める。出発前は`waiting`、制約違反の停止は`blocked`。制約違反の試行を捨てたり修正したりしない。

計算負荷を制限するため、全経路のサンプル点数は200万点、ノイズ生成の各経路は10万点、各区間の分割は2万まで。上限超過はエラーとして入力を保持する。

## 探知・ミッション・分析

[sensor、detectability、mission、analysisの完全な定義](detection-model.md)。分析結果のファイルも`.jsn`で、`type: "SimSim-analysis"`によりシナリオと区別する。アプリの「開く」でどちらも読み込める。

0.4の追加比較変数・試行ごとの分布・結果version 2は[統一パラメータモデル](parameter-model.md)を参照。シナリオ自身のversionは1のまま。
