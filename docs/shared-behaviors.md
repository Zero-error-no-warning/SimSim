# 共有挙動と計算済み記録の再生（0.7.0-dev）

ブランチ: `feat/shared-behavior-replay`。mainへ未統合。静的HTTP・module Worker・同梱Three.jsを維持する。eval・外部CDN・サーバ側処理は使用しない。初回の実装範囲は周回監視・報告・帰投・待機・終了の共有グラフと、その担当群内の間隔調整。

## データと実行

新規サンプルはシナリオversion 2。従来version 1も読み込めるが、旧ルールと共有挙動を同一シナリオで併用する計算は未対応。既存の地形・能力属性・群生成・乱数・分析形式を流用し、新しい実行エンジンを分離した。

| 正本 | 内容 |
| --- | --- |
| `behaviors[]` | id、name、entry、nodes、edges。挙動の再利用可能な定義 |
| `behaviorAssignments[]` | id、name、behaviorId、targets、route、base、spacing、spacingDistance、gain。協調グループと実行条件 |
| `units[]` / `groups[].template` | 領域、最大移動速度、センサー・通信能力、移動のばらつき |
| `recording` | step（計算刻み）、interval（通常記録間隔） |
| `mission` | 成否・期限の評価。共有挙動の探知・行動自体を制限しない |

ノードのkindはpatrol/report/return/wait/stop。巡回のspeedFractionは各個体の抽出後速度の0.05～1。wait.secondsは1秒以上。report.receiverIdは単体ユニット。edgesはfrom/to/whenを持ち、同じ始点と条件の接続は一つ。条件はdetected/sent/sendFailed/arrived/elapsed/received。報告はノードへの進入ごとに一回。発見は観測側と対象の組合せごとに初回のみ。継続追尾・再探知・燃料条件・交戦・JavaScript拡張は未実装。

割り当てtargetsは`unit:ID`または`group:ID`。各単体・群は一つの協調グループに割り当てる。定義は複数グループで共有できる。実行中ノード・位置・探知情報は各機独立。挙動の変更はそれを使う全グループへ適用し、経路・基地・間隔方式はグループごとに異なる。

routeは閉じた周回の3点以上の配列。baseは帰投先の座標。開始ノードが周回の場合、グループの機体を経路上へ初期配置する。even/fixedは初期位置を等間隔に導出し、noneは個体のloopStartを使う。巡回への再進入は現在位置から近い経路点へ移動して合流し、瞬間移動しない。帰投は指定高度・深度の地点へ直線的に移動し地形制約を確認する。着陸・離陸・浮上・障害物を迂回する経路探索は未実装。

## 協調する間隔

patrolにいる機体を経路上の進捗で並べ、前方機との間隔との差から速度を調整する。evenでは現在監視中の機体数から間隔を再算出。fixedでは指定距離。帰投・待機・地形停止中の機体は調整対象から外す。調整係数gainは1/s、速度は0～各個体の能力上限。加速度・旋回半径は未モデル化。

経路上の間隔は空間の直線距離と異なる。全機の指定間隔×個数が周回長と異なる場合、固定間隔をすべて同時に満たせない。また速度上限やばらつきにより完全に等間隔へ収束することを保証しない。航跡のずれがある場合、各機の経路長に対する進捗を基準にした近似。

## 計算・再生・保存

編集時は初期状態のみ表示し、共有挙動の再生は「計算・記録」の完了後に有効になる。計算Workerがstep刻みで全体を進め、探知をステップ末尾の位置と区間の長さで抽選し、切替は次の移動ステップへ反映する。通信の受信は遅延後の最初のステップ境界で処理する。時刻に対する近似はstepに依存するため、刻みを小さくした比較が必要。

通常の記録間隔に加え、ノード切替、曲がり角、地形停止、到着などで全体フレームを記録する。位置XYZ・向き・移動距離はFloat32Array、ノードはUint16Array、状態はUint8Array。各機・各フレーム23バイト＋時刻8バイト。256MiBの記録配列上限。通常間隔を広げても多数の曲がり角で記録が密になる場合がある。

再生は二つの記録フレームを参照して位置・向き・移動距離を補間し、ノード・状態・イベントは記録時刻に従う。表示速度は記録区間の平均値。乱数・探知・協調制御は実行しない。Workerは記録を保持し、画面へ現在時刻のスナップショットだけを送る。

`SimSim-recording` version 1 / model `shared-behavior-v1` は元シナリオ、単体ID、ノードID、評価とイベント、時刻、配列のbase64を含むJSONテキスト。拡張子は`.jsn`。byte-orderは作成環境の型付き配列に従う。保存・読み込み時は文字列・変換用配列分の追加メモリが発生する。読み込みは構造・時刻・配列長・有限値等を検証し、記録を再計算しない。入力シナリオから記録内容の物理的整合を再検証する方式ではない。

モンテカルロは同じエンジンを使い、記録配列なしで試行の集計だけを返す。全試行のイベント列を保持しない。選んだ試行はシード・抽出値から一度計算して記録し、以後の時刻移動は記録だけを見る。共有挙動の分析保存は`SimSim-analysis` version 4。結果の読み込みは再集計で、試行の再計算ではない。

## 操作

「共有挙動」でノードをドラッグし、右の丸→接続先の左の丸で接続する。出力側を選ぶと、その種類に合う標準条件を選ぶ。接続条件は変更可能。条件ラベルの×をクリックするとその接続を削除。ノード選択で設定・開始指定・削除。ローカルUndo/Redoを備え、適用はシナリオの一回のUndoになる。

同じ画面で協調グループを追加し、共有挙動と担当する単体・群を選ぶ。共有経路は地図の順次クリック（3点以上）→Esc、帰投先は地図クリック。選択ユニットの既存経路を取り込む操作もある。複数選択はブラウザのselect操作による。共有経路の地図ドラッグは同じ割り当ての全担当へ適用する。割り当てられたユニットの旧経路数値欄は共有経路の案内へ切り替える。

報告先のユニットを削除すると定義の検証で不正を検出するため、先に報告先を変更する。群削除時は担当参照と、空になった協調グループ・関連する分析変数を整理する。

## 初回検証

純粋計算: 共有グラフ・独立状態・報告成功／失敗・帰投・到着・間隔の偏りの改善・順序独立性・記録の往復・スライダー相当の時刻参照で計算回数不変・全試行記録なし・分析version 4・1000機1時間。

1000機＋2単体、1時間、1秒計算、通常10秒記録では3601フレーム・約79.17MiBの配列。各機の曲がり角時刻が分散するため実際は毎秒記録された。Nodeの実行時間は検証環境で約3～6秒。総プロセスメモリ・社内PC性能を示す値ではない。

ブラウザ: 静的HTTP `/SimSim/`、自己オリジンのみのCSP、ソフトウェアWebGL、1600×1100と390×844。ノードのドラッグ・接続・削除・Undo、属性と割り当ての適用、計算と再生、記録保存・読み込み、時刻移動後の同じ記録、再計算、6条件×2試行のWorker分析・version 4保存／復元・試行再現を確認。共有経路の地図作図、帰投地点の指定、図の拡大と全体表示も確認。ブラウザでも1000機＋2単体・1時間の計算と79.17MiBの記録・時刻の前後移動を確認。従来の地図操作（3D・1000個の群を含む）も回帰確認。
