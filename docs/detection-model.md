# SimSim 0.3 探知・成功条件・モンテカルロ

静的HTTP配信、Web Worker内の計算。サーバ側の計算・保存・動的通信は不要。モデル名は`range-hazard-v1`。実装は`src/detection.js`に分離し、将来の性能モデルと置き換えやすい構成。

## ユニット・群の探知設定

```json
{
  "detectability": 1,
  "sensor": {
    "enabled": true,
    "range": 600,
    "probabilityPerMinute": 0.25,
    "domains": ["surface", "subsurface"],
    "terrainLOS": true,
    "mountHeight": 0
  }
}
```

単体または群の`template`へ追加する。複数センサーの並列構成は未実装。

| フィールド | 定義 |
| --- | --- |
| `detectability` | 0～10、既定1。0はこのモデルで探知不能。対象の探知頻度への倍率 |
| `sensor.enabled` | boolean、必須 |
| `sensor.range` | 最大距離m、0より大きく100000以下、必須 |
| `sensor.probabilityPerMinute` | 距離0、被探知係数1で60秒間接触した場合の探知確率。0～1、必須 |
| `sensor.domains` | 対象領域の配列。ground/surface/subsurface/airから1個以上、必須 |
| `sensor.terrainLOS` | 地形による直線遮蔽を判定するboolean、必須 |
| `sensor.mountHeight` | ユニット位置から上方への取付高m、0～1000。未指定は地上2m、それ以外0m |

距離0で1分の確率を`p`、距離を`d`、最大距離を`R`、被探知係数を`q`、区間秒を`dt`とすると:

- `lambda = -ln(1-p) / 60`
- `P(dt) = 1 - exp(-lambda * dt * q * (1-d/R)^2)`（`0 <= d < R`）
- 範囲外、対象領域外、q=0、p=0、遮蔽ありの場合はP=0。
- p=1は、q>0かつ範囲内・遮蔽なしの接触区間で確実に探知する。

これは一定の探知頻度を仮定した簡易モデル。音響伝搬、電波伝搬、海面をまたぐ媒質変化、指向性、識別、誤警報、センサーの故障、通信・司令部への報告は含まない。被探知係数は特定の物理量（RCS等）を直接表すものではない。

各観測側・対象側・時間区間の独立した抽選で、最初に成立した探知を記録する。複数センサーが同じ区間で成立する場合、決定的な処理順で最初の1件を記録する。時刻の分解能は判定間隔までで、同区間内の厳密な最先着センサーを選ぶモデルではない。

## 判定時刻・地形

各区間の中点位置で距離・見通しを評価し、その区間の末尾時刻で探知を記録する。区間末尾は期限に合わせて短縮する。時刻0では確率抽選をしない。取付高はセンサーに、地上対象には固定2mの高さを足す。

地形との直線比較は、地形格子間隔の1/4または125mの小さい間隔でサンプリングする。地形標高より低く通る線、地形範囲外を通る線は遮蔽する。海面は遮蔽物として扱わない。地球曲率、屈折、建物、厳密な地形交差は未実装。

短時間の接触が判定区間の間に入る場合、見逃し得る。間隔を小さくして結果が安定するか確認する。異なる判定間隔で同一の抽選値になることは保証せず、間隔も再現条件の一部。

初期位置が地形制約に反したユニットは観測・探知対象として機能しない。途中で移動が地形制約に反すると、その地点で停止するが、停止を破壊・故障とは見なさずセンサーは機能し続ける。無効な初期配置・制約付き経路を試行から除外／再抽選しない。

## 成功条件

```json
{
  "mission": {
    "type": "detect",
    "observerFaction": "friendly",
    "targetFaction": "hostile",
    "join": "any",
    "deadline": 1000
  }
}
```

| フィールド | 定義 |
| --- | --- |
| `type` | `detect` |
| `observerFaction`, `targetFaction` | friendly/hostile/neutral。互いに異なる陣営 |
| `join` | any: 対象の一つ以上を初回探知、all: 全対象を初回探知 |
| `deadline` | 秒。0より大きくシナリオ終了時刻以下 |
| `targetIds` | 任意の重複しないID配列。指定時はこの集合だけを評価（すべて対象陣営に属する必要がある） |

対象が存在しない条件はエラーとして表示し、移動の表示は継続する。観測側が0個なら未成立。成功時刻はanyの最初の探知、allの最後の探知。探知後も、他の対象の初回探知を期限まで収集する。過去へ時刻移動すると、その時刻以前の記録だけを表示する。

## 個数比較

```json
{
  "analysis": {
    "groupId": "observers",
    "counts": [0, 100, 300, 1000],
    "trials": 50,
    "step": 10,
    "requiredRate": 0.95
  }
}
```

| フィールド | 定義 |
| --- | --- |
| `groupId` | 比較対象の群ID |
| `counts` | 重複しない0～2000の整数、最大12条件。0はその群だけを除外 |
| `trials` | 各条件1～2000回。条件数×試行数は10000以下 |
| `step` | 判定間隔1～300秒。シナリオ全体で2万区間以内 |
| `requiredRate` | 比較用の要求成功率、0～1。実際の必要数の保証ではない |

各条件で同じシード、同じ開始試行番号から同じ回数を試す。単体と比較対象以外の群を維持し、合計2000個まで。ランダム配置の場合は既存メンバーの固定IDと乱数を維持する。格子配置の場合は個数で既存位置も変わる。

探知の乱数はシード・試行番号・観測側ID・対象側ID・区間の開始／終了時刻から決まる。描画や評価順では乱数ストリームを消費しない。比較で軌跡・配置・探知抽選を揃えるための仕組みで、推定成功率の差に専用の検定を行う機能は未実装。

## 集計と再現

- 成功率=成功試行数/完了した試行数。未成立率=1-成功率。
- 95%信頼区間はWilson法の両側区間。式の参照: [NIST, Confidence intervals](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)。複数条件を同時に保証する区間ではない。
- 要求率を満たす「最少の比較点」を表示する。比較していない個数の補間や、実際の必要数の保証はしない。
- 成立時刻の中央値は成功した試行だけの条件付き集計。未成立試行は無限大として混ぜず、率で別に表す。
- 初期配置不正の試行数は、1個以上のユニットに初期位置不正がある試行数。対象の成否を機械的に全失敗へ変更する値ではない。
- 中止時は最後に画面へ送った完了試行だけを残す。部分結果であることを表示する。
- 再現時は保存している分析元の定義を使い、個数・試行番号を変更して計算し直す。通常の編集では旧結果を破棄する。

別Workerで分析し、位置の全履歴はバッチ中に保存しない。空間格子で近くの観測側を検索する。進捗・中止に対応し、移動表示のWorkerと独立している。

## 保存済み分析結果

`.jsn`、`type: "SimSim-analysis"`、`version: 1`、`model: "range-hazard-v1"`。分析元のシナリオを`source`、各条件の試行要約を`rows[].trials`へ含める。各試行にはtrial, success, successTime, targetCount, detectedCount, invalidUnits, constrainedPathsを保存する。全位置の履歴は含めない。

読み込み時は形式・試行番号・成否と探知数・成立時刻を検証し、率・区間・中央値を再集計する。保存済み成否をモデルで再計算した結果ではないため、その旨を表示する。再現ボタンでは現在のモデルで計算し直す。

信頼区間が示すのは、指定したモデルと入力で乱数試行を有限回行った誤差の目安。モデルの現実への適合、入力性能値、共通環境の不確実性、試行数以外の誤差を包含するものではない。同梱サンプルはすべて架空のソフトウェア動作確認用。
