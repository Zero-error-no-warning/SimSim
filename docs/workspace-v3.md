# SimSim 0.8 — 現在の操作と設計

2026-10-05。対象は `feat/shared-behavior-replay`。0.7の全体レビューに基づく改修版です。旧資料はこのページへ案内を統一しています。

## 画面の考え方

地図で配置と経路を操作し、選んだ対象の詳細を右で編集します。上部は新規・サンプル・開く・保存・分析、地図の上は編集と視点操作、下は計算・再生です。表示オプションは「表示」、シード・計算刻み・終了時刻は「計算設定・乱数シード」にまとめています。

| 概念 | 担当すること | 保存先 |
|---|---|---|
| ユニット／群 | 領域、速度、有人無人、センサー、被探知性、通信能力 | `units` / `groups[].template` |
| 挙動 | 周回、情報待ち、報告、帰投などのノードと条件接続 | `behaviors` |
| タスク | 挙動を誰がどの経路・報告先・開始割合で実行するか | `behaviorAssignments` |
| 成功条件 | 何をいつまでに探知／到着すれば成功か | `mission` |
| 分析条件 | 比較する変数と、試行ごとに抽出する分布 | `analysis` |
| 再生記録 | 計算済み位置・状態・ノード・イベント | 別の記録ファイル |

「共有挙動」と旧「行動・通信」という二つの行動設定画面は廃止しました。現在は、タスクの「担当・経路」と「挙動のノード」の二つのタブです。通信の距離・遅延・成功確率はユニットの能力欄にあります。

同じ挙動を複数のタスクで再利用できます。タスクの共有経路を使う担当者は、そのタスク経路を編集します。共有経路を持たないタスクやタスク未割当のユニットは個別経路を使います。タスク未割当でも計算は同じモデルで行われます。単体または群は同時に一つのタスクだけに担当できます。群は同じひな型の複数個体であり、タスクとは別の概念です。

## 地図と選択対象の編集

地図かユニット一覧で選択し、「配置編集」で記号をドラッグすると経路全体を移動します。群の一個体を動かすと群全体が対象になります。番号付き経由点をドラッグするとその点を編集し、選択してDeleteで削除します。共有経路の場合、地図・経由点表・削除・高度／深度設定が同じタスクの経路を変更します。

右クリックまたは「操作」から追加・複製・経由点追加・周回経路作成を行います。配置は地図クリックで確定、Escで取り消します。周回経路は中心→円周の順にクリックします。選択中の担当者を複製すると、同じタスクの担当も引き継ぎます。領域変更で共有経路の意味が変わる場合は、先に担当を解除してください。

生成された群の個体属性は読み取り専用です。「この群を編集」からひな型・個数・ばらつきを変更します。共有経路を使う群では、使われない配置幅や古い初期位置を編集させず、タスク側へ案内します。報告先として使っている単体の削除は、報告先を変更してから行います。

Fは選択へ移動、Spaceは再生／停止、Ctrl/Cmd+Dは複製、Ctrl/Cmd+ZはUndo。RedoはCtrl/Cmd+Shift+ZまたはCtrl/Cmd+Yです。新規作成は現在の地形を残し、ユニット・群・挙動・タスク・成功条件・分析条件を消去します。Undoで戻せます。履歴上限は25回です。

## タスクとノード

左のタスク、または右の「担当タスクを設定」から開きます。選択中の担当タスクが編集対象になります。「担当・経路」で担当者、使う挙動、報告先、共有経路、帰投地点、出発割合、間隔調整を設定します。「挙動のノード」でノードを移動し、右の丸→接続先の左の丸をつなぎます。接続条件は始点が発生させるイベントから選べます。

起動条件は紫色の丸みのあるノード、処理は青色のノードです。「開始ノードにする」は廃止しました。起動条件を選択し、右の丸から処理の左の丸へ接続するか、右欄の「開始する処理」で接続先を選びます。途中の「情報を待つ」「時間待ち」は処理に入り、その後のイベントを待つ動作です。

| 起動条件 | 発生するタイミング |
|---|---|
| シーン開始 | 計算の0秒時点 |
| 情報受信 | 担当ユニットに通信が届いた時点 |
| 指定時間経過 | シーン開始から指定した秒数。処理開始からの待機時間とは別 |
| 対象探知 | 担当ユニットのセンサーが対象を初めて探知した時点 |

同じ挙動に複数の起動条件を置けます。まだ起動していない担当者は経路始点で停止し、起動条件の成立を待ちます。初期配置や経路の地形違反は従来と同様に停止理由になります。実行中に届いたイベントは標準では新しく起動せず、現在のノードの接続で処理します。「実行中の処理を中断して起動」を選ぶと起動条件を優先します。「終了」は実行終了として次の起動条件を受けられますが、探知はしません。

各起動条件は標準で各個体に一度だけ発火します。情報受信・探知はチェックを外して繰り返し起動できます。シーン開始・指定時刻は一度だけです。実行中に見送ったイベントを後から実行することはありません。同じイベントの入口は一つ、指定時刻は時刻が異なれば複数置けます。通常ノードから起動条件には接続できません。

ホイールでカーソル位置を中心に拡大縮小、背景ドラッグで移動できます。「全体表示」で起動条件も含む全ノードを収めます。右下のミニマップは現在の表示範囲を枠で示し、クリック・ドラッグでその位置へ移動します。ノードの移動は拡大縮小後も図の座標で保存します。

データはグラフの `triggers` に保存します。従来の `entry` は読み込み時に `scenarioStart` の起動条件へ変換し、保存時には出力しません。

```json
{
  "id": "respond", "name": "情報受信で対応",
  "triggers": [
    {"id":"on-start", "event":"scenarioStart", "to":"patrol", "x":40, "y":70},
    {"id":"on-message", "event":"received", "to":"respond", "policy":"interrupt", "once":false, "x":40, "y":190},
    {"id":"at-300", "event":"time", "seconds":300, "to":"respond", "policy":"interrupt", "x":40, "y":310}
  ],
  "nodes": [{"id":"patrol", "kind":"follow", "x":340, "y":70}, {"id":"respond", "kind":"return", "x":340, "y":190}],
  "edges": []
}
```

起動条件は1～32件。`id` はグラフ内の起動条件間で一意の英数字・`_`・`-`、1～80文字。`event` は `scenarioStart|received|time|detected`。`to` は処理ノードID。`seconds` は `time` のとき必須で0～86400秒。`policy` は `idle`（標準）または `interrupt`。`once` はboolean（標準true）。`x/y` は図上の位置（0～4000）。情報受信・探知の起動時には、その情報を報告ノードへ引き継ぎます。

| ノード | 接続に使える条件 |
|---|---|
| 経路を進む | 探知・情報受信・到着 |
| 協調して周回 | 探知・情報受信 |
| 情報を待つ | 情報受信・探知 |
| 報告 | 送信成功・送信失敗 |
| 帰投 | 到着・情報受信・探知 |
| 時間待ち | 待機終了・情報受信・探知 |
| 終了 | なし |

一つのノードから同じ条件の接続を複数作ることはできません。接続の `once` はその個体で一度だけ遷移する指定です。ノードのセンサー設定で、その状態中に探知を行うかを切り替えます。「終了」では探知しません。ノードにない条件で接続したファイルは読み込めません。

報告は固定の単体へ送るか、タスクの報告先を使います。後者は同じグラフを別の基地向けタスクで再利用できます。中継時には発見対象・観測位置・元の観測者を保持します。通信は距離・地形の直線見通し・成功確率で判定し、送信成立後に指定遅延で届きます。複数の報告が同時に届く場合も、それぞれの受信情報で処理します。即時遷移や通信の無限循環には明示的な上限があります。

周回の出発割合は0～100%です。群内の同位置・均等・ランダムな出発割合と、タスク全体の割合を組み合わせます。経由点番号ではなく経路長に対する割合です。協調間隔は経路上の位相差を速度調整で近づける簡易モデルで、3Dの直線距離を常に厳密に保つ制御ではありません。

帰投は現在地からタスクの帰投地点への直線経路です。障害物の自動回避はありません。速度はその試行の速度ばらつきも反映します。タスク未割当は個別経路を定速で進み、一度だけ・往復・周回が使えます。

## 計算と再生

編集後は記録が無効になり、「未計算」と表示されます。「計算」でWorker内で終了時刻まで計算し、完了してから再生できます。中止と失敗を未計算・完了から区別します。再生速度と時刻スライダーは記録を見るための操作です。巻き戻しでシミュレーションは再計算せず、航跡も同じ記録から生成します。

探知の試行は固定の計算刻みで行います。通信受信、準備完了、到着、成功条件の期限は、刻みの間にあってもその時刻で処理します。記録は通常間隔に加え、移動区間・状態・ノードが変わる時刻にも残します。フレーム間の位置は直線補間、状態とノードは直前の記録を使います。計算刻みを変更した際は、短い接触の見逃しについて刻みを細かくした結果と比較してください。

位置などをFloat32、ノードをUint16、状態をUint8で保持します。生の記録上限は128MiB、保存ファイル上限は256MiB、フレームは100001件までです。1000個＋2単体・1時間の試験では約79.2MiB、3602フレームになりました。これは記録配列の大きさで、ブラウザ全体の使用量ではありません。経由点・イベントが多いと通常間隔以上に増えます。現在は全体フレーム方式なので、個体ごとの変更区間だけを保存する圧縮は未実装です。

## 分析と統一パラメータ

分析では成功条件、比較変数、試行数、要求率、試行ごとのばらつきを設定します。対象と性能を別々に選びます。群の個数も通常の比較変数です。複数比較変数は全組合せ、一様・三角分布は試行ごとの抽出です。

パラメータ台帳は意味・単位・検証範囲・保存先を一つに結びます。State／Capacity／Extent／Rateに加え、確率・挙動・ミッションの項目を登録します。同じ値を別の属性オブジェクトへ二重保存しません。

現在扱える変数は、移動速度、探知距離・確率・取付高、被探知係数、通信距離・遅延・成功確率、群の個数、配置・個別経路の位置、周回の開始割合、航跡の水平／上下ずれ・変動間隔・出発遅れ・速度ばらつき、共有経路の位置・開始割合、間隔調整、タスクの準備時間、成功条件の期限です。能力を登録すれば物理作用まで自動実装されるわけではありません。燃料・電池・補給・交戦などの状態更新は今後の実装です。

共有経路を使う担当者の古い位置・配置幅・個別の周回開始値は分析候補から除外します。代わりにタスクを対象とする変数を選びます。群の個数0では担当が消えても計算モデルや判定刻みは変わりません。削除時は分析参照も整理します。無効な参照は実行前に拒否します。

乱数シードと試行番号で抽出・航跡・接触・通信を再現します。同じ試行番号では能力比較に対応する乱数を共有します。行動により観測回数や配置が変化する比較で、結果の単調増加を一般に保証するものではありません。

図の横軸は数値に応じた間隔で、線形／対数を選べます。個数0は対数図から除外されますが表には残ります。成功率とWilsonの両側95%信頼区間、未成立率、成功時刻の中央値を表示します。要求率は比較の目安です。分析は詳細位置を保存せず、一つの試行を「再現」したときにその試行だけを計算・記録します。

## 地形・探知とサンプル

座標はローカルのx/y/z、距離m、時間s。地上は標高へ投影、水上は海面、水中と空中は深度・高度を使います。地形格子と経路を照合し、制約違反を理由付きで停止します。自動探索・再配置はしません。見通しは地形による直線遮蔽の近似で、海洋音波伝搬ではありません。

探知は最大距離内で試行し、距離減衰・被探知係数・時間幅から確率を計算します。センサーの対象領域と陣営を参照します。成功条件の観測側・対象側を変えても、物理的な探知や条件付き行動そのものを切り替えません。評価は期限内の対象一つ／すべての初回探知、または指定単体の到着一つ／すべてです。継続追尾・接触品質・通信ネットワーク最適化は未実装です。

起動サンプルは二島間を通る潜水艦と、島を周回するUUVです。個数4／8／16／32×距離0.75／1.5／2.5km、12条件×50試行。その他は上部の「サンプル」から選びます。7サンプルをversion 3へ更新しています。地形と性能はすべて架空で、実装確認用です。

## 保存形式と旧版からの移行

| ファイル | 形式 | 内容 |
|---|---|---|
| シナリオ | `version: 3` | 地形、能力、経路、挙動、タスク、成功条件、分析条件、記録設定 |
| 分析結果 | `type: SimSim-analysis`, `version: 5` | 元定義・条件・各試行・抽出値・モデル識別子 |
| 再生記録 | `type: SimSim-recording`, `version: 2` | 元定義・対象ID・ノード名・配列・評価とイベント |

計算モデル識別子は `trigger-behavior-v3`。JSON内容を `.jsn` で保存します。`.json` の手動読込も可能です。記録読込では配列長・時刻・有限値・状態・担当ノード・イベント参照と位置を検証し、分析読込では抽出値とシード／分布の一致、件数と成否を検証します。分析結果の読込時に試行を再計算するわけではありません。

旧シナリオの `behavior.hold/preparation/rules` は読込専用の変換境界で処理し、挙動とタスクへ変換します。同じ条件に複数の旧ルールを置くなど、意味を保って変換できないケースは拒否します。旧ルールと既存タスクの重複も拒否します。変換後に保存するとversion 3です。旧分析結果・旧再生記録は旧版で開き、必要なら元シナリオ定義を新版で読み込んで再計算してください。旧計算値を新版の計算値と同一視しません。

共有経路はタスク、個別経路はユニット／群のひな型が正本です。編集コマンドが対象を解決します。独立したルートID台帳への全面移行は今回行っていません。

| `shared-settings.js`, `recorded-engine.js` | ノード／タスク検証、唯一の行動・通信・探知実行モデル |

旧 `actions.js` と `action-ui.js` は削除しています。通常・タスクの有無による実行系選択はありません。幾何基盤の `Simulation` の単体テストと、公開実行モデルの `RecordedSimulation` を区別します。

## 検証

`node --test tests/*.test.mjs` は12テストファイル。地形・経路・乱数・編集・探知・パラメータ・周回・条件付き応答・共有挙動・統合回帰を確認します。`triggers.test.mjs` は刻み間の指定時刻、起動前の停止、複数入口・中断・一度／繰り返し、受信情報の中継、因果循環、旧entry変換、起動前の記録再読込を確認します。`integration.test.mjs` は全体レビューA01～A07に対応する正しい挙動、共有経路編集、個数0、分析参照、ノード条件、記録検証、航跡の時刻移動を含みます。

`tests/browser-smoke.mjs` は静的 `.jsn` 配信と外部通信禁止CSPで、起動、選択中タスク、タブ、起動条件の接続・編集、カーソル中心のホイール拡大縮小、背景移動、全体表示、ミニマップ、拡大縮小後のノード移動、条件選択、定義保存、Worker計算、巻き戻し、記録保存／読込、新規／Undo、モンテカルロ／試行再現、ラベルトグル、1600pxと390pxの横はみ出し、ブラウザエラーなしを検証します。

1000個＋2単体・1時間の記録、島サンプル600試行、探知→中継→準備→出発→到着サンプル600試行を計算テストに含みます。実行速度は環境依存です。社内ブラウザ・GPU・配信設定の実動作は移設後にも確認してください。

[0.7時点の全体レビュー](architecture-audit-2026-10-04.md) は当時の問題と改修計画の記録です。今回の残りの課題は、記録の個体単位圧縮、経路の独立台帳、より大きいノードグラフの操作性、実地形入力と追加の専門モデルです。
