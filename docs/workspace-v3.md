# SimSim 0.8 — 現在の操作と設計

2026-10-05。対象は `feat/shared-behavior-replay`。0.7の全体レビューに基づく改修版です。旧資料はこのページへ案内を統一しています。

## 画面の考え方

地図で配置と経路を操作し、選んだ対象の詳細を右で編集します。上部は新規・サンプル・開く・保存・分析、地図の上は編集と視点操作、下は計算・再生です。表示オプションは「表示」、シード・計算刻み・終了時刻は「計算設定・乱数シード」にまとめています。

| 概念 | 担当すること | 保存先 |
|---|---|---|
| ユニット／群 | 領域、速度、有人無人、センサー、被探知性、通信能力 | `units` / `groups[].template` |
| 挙動 | 周回、情報待ち、報告、目的への移動などのノードと条件接続 | `behaviors` |
| タスク | 挙動を誰がどの担当値・報告先・開始割合で実行するか | `behaviorAssignments` |
| 経路・目的地 | 複数の経路、地点・ユニットの目的地 | `routes` / `destinations` |
| 成功条件 | 何をいつまでに探知／到着すれば成功か | `mission` |
| 分析条件 | 比較する変数と、試行ごとに抽出する分布 | `analysis` |
| 再生記録 | 計算済み位置・状態・ノード・イベント | 別の記録ファイル |

「共有挙動」と旧「行動・通信」という二つの行動設定画面は廃止しました。現在は、タスクの「担当・共有設定」と「挙動のノード」の二つのタブです。通信の距離・遅延・成功確率はユニットの能力欄にあります。

同じ挙動を複数のタスクで再利用できます。タスクの共有経路を使う担当者は、そのタスク経路を編集します。共有経路を持たないタスクやタスク未割当のユニットは個別経路を使います。タスク未割当でも計算は同じモデルで行われます。単体または群は同時に一つのタスクだけに担当できます。群は同じひな型の複数個体であり、タスクとは別の概念です。

## 地図と選択対象の編集

地図かユニット一覧で選択し、「配置編集」で記号をドラッグすると経路全体を移動します。群の一個体を動かすと群全体が対象になります。番号付き経由点をドラッグするとその点を編集し、選択してDeleteで削除します。初期状態が名前付き経路を選んでいる場合、地図・経由点表・削除・高度／深度設定はその名前付き経路を変更します。複数のノードで同じ経路を使っている場合、その全てに反映されます。旧タスク経路の場合は同じタスクの経路を変更します。

PCのマウス・キーボード操作を前提にしています。地図の空白を右クリックするとユニット追加・地形編集、ユニットや左のユニット一覧を右クリックすると対象の設定・担当タスク・複製・経路編集・削除が開きます。経由点には点の編集操作だけを表示します。上部の「操作」プルダウンは廃止しました。配置は地図クリックで確定、Escで取り消します。周回経路は中心→円周の順にクリックします。選択中の担当者を複製すると、同じタスクの担当も引き継ぎます。領域変更で共有経路の意味が変わる場合は、先に担当を解除してください。

生成された群の個体属性は読み取り専用です。「この群を編集」からひな型・個数・ばらつきを変更します。共有経路を使う群では、使われない配置幅や古い初期位置を編集させず、タスク側へ案内します。報告先や目的地として使っている単体の削除は、参照先を変更してから行います。

Space＋左ドラッグは3Dで回転、真上表示では平行移動。地形・経路・配置の編集途中も使え、操作中は編集しません。Shift＋Space＋左ドラッグ、右または中ボタンのドラッグで平行移動し、ホイールで拡大縮小します。Fは選択へ移動、Ctrl/Cmd＋Spaceは再生／停止、Ctrl/Cmd+Dは複製、Ctrl/Cmd+ZはUndo。RedoはCtrl/Cmd+Shift+ZまたはCtrl/Cmd+Yです。新規作成は現在の地形を残し、ユニット・群・挙動・タスク・経路・目的地・成功条件・分析条件を消去します。Undoで戻せます。履歴上限は25回です。

## タスクとノード

左のタスク、または右の「担当タスクを設定」から開きます。選択中の担当タスクが編集対象になります。「担当・共有設定」で担当者、使う挙動、報告先、出発割合、間隔調整を設定します。経路・目的地の作成と選択は状態ノードの編集欄から行います。「挙動のノード」は、まず図上にノードや線を作り、クリックして内容を設定する順番で編集します。

図の空白を右クリックして「ここに状態ノードを作る」または「ここにイベントノードを作る」を選ぶと、その位置に作成します。「＋追加」から作ることもできます。未設定のノードが表示され、作成時に選択されます。ノードをクリックすると右の編集欄で種類を設定できます。状態ノードは青色、イベントノードは紫色です。種類を決める前に線をつなぐこともできます。

シーン開始ノードはありません。状態ノードを選択して「初期状態」にチェックすると、シーン開始時にその状態へ入ります。図には「初期状態」の目印が表示されます。別の状態を初期状態にすると、以前の指定は外れます。初期状態を指定しない場合は、イベントが発生するまで経路始点で待機します。初期状態もイベントノードもない挙動は適用できません。

ノードを右クリックして「ここから接続」を選び、接続先の状態ノードをクリックします。Shift＋クリックで接続元を選ぶ方法や、「接続」ボタンから接続元→接続先を選ぶ方法も使えます。入力点・出力点はありません。接続元を緑色で表示します。背景クリック、Esc、または「接続をキャンセル」で取り消せます。通常のクリックは編集、ドラッグは移動です。同じ状態を二回選ぶと自己遷移になります。「終了」を接続元にはできず、イベントノードを接続先にはできません。

状態同士の線は「条件を設定」と表示され、線またはラベルをクリックして右の「遷移する条件」を選びます。条件は始点の状態が発生させるイベントから選べます。線を再選択すれば条件を変更でき、削除は線の右クリックメニュー、または線を選択してDeleteで行います。線のクリックだけでは削除しません。同じ始点の別の線で使用中の条件は選べず、既存の分岐を自動で置き換えません。

ノードの種類を変更して遷移条件が使えなくなった場合、接続は残して条件を未設定に戻します。線を選んで条件を設定し直してください。「終了」からの線は削除するか、始点の種類を変更します。未設定のノード、未接続のイベントノード、未設定の遷移線を含む編集は、設定を完成させてから適用します。初期状態の変更・編集・接続・種類変更はUndo/Redoで戻せます。

イベントノードから状態ノードへの線は、共通の割り込み遷移先を表します。線に別の遷移条件は付けません。イベントが発生すると、現在の状態の処理を中断して接続先の状態へ入ります。同じイベントに対応する状態間の遷移線より優先します。イベントノードを選択し、「遷移先の状態」でも接続先を設定できます。「一度だけ／繰り返し」を各イベントノードで選択します。一度だけのイベントを使用済みの場合は、以降そのイベントを状態間の遷移線で処理できます。終了状態でも受信・時間イベントによる遷移が可能ですが、終了状態は探知を行いません。

| イベント | 一度だけ | 繰り返し |
|---|---|---|
| 情報受信 | 最初の通信受信で遷移 | 通信が届くたびに遷移 |
| 時間経過 | シーン開始から指定秒数後に遷移 | シーン開始から指定秒数ごとに遷移 |
| 対象探知 | 最初の対象探知で遷移 | 新たな対象を探知するたびに遷移 |
| 指定距離まで近づく | 最初に目的から指定距離以内になった時に遷移 | 範囲外へ出た後、再び範囲内になった時に遷移 |

発火回数は担当ユニットごとに管理します。対象探知は同じ対象の毎刻みの再検出を意味しません。「情報を待つ」「時間待ち」は、その状態に入ってからイベントや時間を待つ状態です。時間イベントの基準はシーン開始、時間待ちの基準はその状態に入った時刻です。初期配置や経路の地形違反による停止は従来と同様です。

同じ挙動に複数のイベントノードを置けます。情報受信・対象探知はそれぞれ一つ、時間イベントは秒数が異なれば複数置けます。接近イベントは目的地・距離・距離の種類が異なれば複数置けます。複数の時間イベントが同時に発火する場合は、定義の順に処理します。状態ノードからイベントノードには接続できません。

ホイールでカーソル位置を中心に拡大縮小、Space＋ドラッグ・中／右ドラッグ・背景の左ドラッグで移動できます。Space操作ではノード位置・選択を変えません。図を操作中のFは全体表示、Ctrl/Cmd+Dは選択ノードの複製、Deleteは選択ノード・線の削除、Ctrl/Cmd+ZとCtrl/Cmd+Shift+Zは挙動図のUndo/Redoです。入力欄の文字編集はこれらのショートカットの対象外です。右クリックメニューは矢印キー・Enterで選べ、Escで閉じます。Shift+F10でもメニューを開けます。「全体表示」でイベントノードも含む全ノードを収めます。右下のミニマップは現在の表示範囲を枠で示し、クリック・ドラッグでその位置へ移動します。ノードの移動は拡大縮小後も図の座標で保存します。

初期状態はグラフの `initial`（状態ノードID）、イベントノードは `triggers` に保存します。従来の `entry` と `scenarioStart` の開始ノードは、読み込み時に `initial` へ変換します。開始ノードと `policy` は保存時に出力しません。旧イベントの `idle` 設定も、現行では共通の割り込みとして動作します。旧記録は記録済みのフレームをそのまま再生し、再保存も可能です。

```json
{
  "id": "respond", "name": "周回中の共通イベント対応",
  "initial": "patrol",
  "triggers": [
    {"id":"on-message", "event":"received", "to":"respond", "once":false, "x":40, "y":190},
    {"id":"every-300", "event":"time", "seconds":300, "to":"respond", "once":false, "x":40, "y":310}
  ],
  "nodes": [{"id":"patrol", "kind":"follow", "x":340, "y":70}, {"id":"respond", "kind":"move", "x":640, "y":190}],
  "edges": []
}
```

`initial` は省略可能ですが、初期状態とイベントノードのどちらかが必要です。イベントノードは0～32件。`id` はイベントノード間で一意の英数字・`_`・`-`、1～80文字。`event` は `received|time|detected|near`。`to` は状態ノードID。`seconds` は `time` のとき必須で0～86400秒、繰り返しの場合は0より大きい秒数。`once` はboolean（標準true）。`x/y` は図上の位置（0～4000）。情報受信・探知では、その情報を遷移先の報告状態へ引き継ぎます。

| ノード | 接続に使える条件 |
|---|---|
| 経路を進む | 探知・情報受信・到着・指定距離まで近づく |
| 協調して周回 | 探知・情報受信・指定距離まで近づく |
| 情報を待つ | 情報受信・探知・指定距離まで近づく |
| 報告 | 送信成功・送信失敗・指定距離まで近づく |
| 目的に向かって進む | 到着・情報受信・探知・指定距離まで近づく |
| 時間待ち | 待機終了・情報受信・探知・指定距離まで近づく |
| 終了 | なし |

一つのノードから同じ条件の接続を複数作ることはできません。接近条件は目的地・距離・距離の種類の組み合わせが異なれば複数指定できます。接続の `once` はその個体で一度だけ遷移する指定です。ノードのセンサー設定で、その状態中に探知を行うかを切り替えます。「終了」では探知しません。ノードにない条件で接続したファイルは読み込めません。

報告は固定の単体へ送るか、タスクの報告先を使います。後者は同じグラフを別の基地向けタスクで再利用できます。中継時には発見対象・観測位置・元の観測者を保持します。通信は距離・地形の直線見通し・成功確率で判定し、送信成立後に指定遅延で届きます。複数の報告が同時に届く場合も、それぞれの受信情報で処理します。即時遷移や通信の無限循環には明示的な上限があります。

周回の出発割合は0～100%です。群内の同位置・均等・ランダムな出発割合と、タスク全体の割合を組み合わせます。経由点番号ではなく経路長に対する割合です。協調間隔は経路上の位相差を速度調整で近づける簡易モデルで、3Dの直線距離を常に厳密に保つ制御ではありません。

「目的に向かって進む」は現在地から指定地点または目的のユニットの計算上の現在位置へ進みます。ユニット目的地は単体ユニットを選択し、位置を計算刻みごとに更新します。探知情報だけに基づく追跡モデルではありません。障害物の自動回避はありません。速度はその試行の速度ばらつきも反映します。旧 `return` ノードは読み込み時に `move` へ変換し、旧タスクの `base` は既存目的地として引き続き使用します。タスク未割当は個別経路を定速で進み、一度だけ・往復・周回が使えます。

## 担当時に指定する値

挙動のノード・条件の編集欄で、値の指定方法から「＋ 担当時に指定する値を作る」を選択し、名前を付けます。同じ種類・単位の既存担当値も選べます。具体的な経路・目的地・数値は「担当・共有設定」の「この担当で使う値」で設定します。同じ挙動を複数の担当で再利用しても、値と実行状態は担当ごとに独立しています。

対応する項目は、経路、移動・接近の目的地、報告先の単体ユニット、待機秒数、巡回速度比、時間イベントの秒数、接近距離です。数値は秒・m・速度比（%表示）に分けます。距離の種類、センサー使用、経路への入り方、発火回数は直接指定します。既定値は省略でき、指定した場合は各担当で「挙動の既定値を使う」か値の上書きを選べます。必須の担当値が未指定、参照先が不明、数値が使用箇所の範囲外の場合は適用・計算前に詳細を表示します。

「担当時に指定する値」ボタンでは名前・既定値を編集し、未使用の値を削除できます。使用中の値や経路・目的地・単体の削除は参照先を変えてから行います。タスクで使う挙動を変更したときは、以前の挙動の担当値を消去します。地図で名前付きの初期経路を編集する操作は、担当値を解決してその経路を更新します。

JSONでは、挙動に `parameters: [{"id":"patrol-route","name":"巡回経路","type":"route"},{"id":"wait-time","name":"待機時間","type":"number","unit":"s","default":30}]` を定義し、ノードの `routeId` や `seconds` に `{"$param":"patrol-route"}` / `{"$param":"wait-time"}` を保存します。タスクの `parameters` は `{"patrol-route":"route-a","wait-time":60}` のようなIDと具体値の対応です。種類は `number / route / destination / unit`、数値の単位は `s / m / ratio`。速度比は保存時0.05～1、表示時5～100%です。担当値は挙動ごとに最大64件です。

サンプル「担当値を変えて挙動を再利用」は、一つの状態遷移図を東航・北航の二つの担当で使い、待機時間・経路・目的地・接近距離を変更します。

## 経路・目的地と接近条件

「経路を進む」「協調して周回」のノードを選び、「使用する経路」で名前付き経路を選択します。「＋新規経路」から作成し、「経路を編集」から変更できます。「＋追加」メニューから、状態を選んでいなくても経路・目的地を作成できます。経路と目的地はシナリオ全体で共有され、複数のノード・挙動から参照できます。

経路には名前、座標列、繰り返し（一度だけ・周回・往復）を保存します。地図で順にクリックし、Escで経路の編集へ戻ります。通常は2点以上、協調して周回する場合は3点以上必要です。座標欄は一行に `x, y, z` をメートルで入力します。地図指定や数値編集をした後、「保存して選択」で挙動の編集に戻ります。取消・Escでは保存せず、経路作成・編集は挙動のUndo/Redoで戻せます。

「経路への入り方」は `joinMode: "start" / "nearest"`。最初からは経路始点へ移動してから、最短地点からは3次元の直線距離が最も近い線分上の点へ移動してから経路を進みます。経由点だけを比較する処理ではありません。障害物を回避した最短経路を探索する機能ではありません。協調周回にも同じ指定があります。初期状態で最短地点を選ぶとユニットの初期位置から接続し、地図でユニットを動かす操作は初期位置のみを変更します（名前付き経路は経由点かノードの編集欄で変更）。最初からを選ぶと経路始点へ配置します。周回の出発割合は、初期状態に「既存の出発設定」を使う場合に適用します。旧データで指定を省略した場合、通常経路は始点、周回への切替は最短地点、初期配置は従来の出発割合を保持します。

別の経路へ切り替える時も現在位置を保持します。「経路を進む」は新しい経路の始点へ接続してから、その経路を進みます。「協調して周回」は近い経路上の点へ接続してから周回します。初期状態では選択経路の出発位置に配置します。別経路を周回している担当者同士の協調間隔は調整しません。旧タスク経路または個別経路は「担当の既存経路」として選択できます。その編集から名前付き経路へ保存して切り替えられます。

「目的に向かって進む」では「目的」で保存済み目的地を選択します。「＋新規目的地」で地点・単体ユニットを作成し、「目的地を編集」で変更できます。地点は地図クリックまたは東西・南北（km）と高さのz座標（m）で指定します。海面が0mなら深度120mのz座標は−120mです。ユニットを目的にすると、移動中のユニットへ向かいます。帰投地点も地点目的地として扱います。編集画面の「編集する経路・目的地」で保存済み項目を選ぶと、ノードへ割り当てずに編集・削除できます。ノードや条件で使用中の経路・目的地は、参照を外してから削除します。

遷移線で「指定距離まで近づく」を選択すると、目的地・距離m・水平距離／絶対距離を指定できます。イベントノードにも同じ条件を指定できます。水平距離はx/yのみ、絶対距離はx/y/zの3次元の直線距離です。状態に入った時点で範囲内なら直ちに条件が成立します。共通イベントで繰り返しを選んだ場合、範囲外へ出てから再び範囲内になる必要があります。連続して範囲内にいるだけでは繰り返し発火しません。

距離条件はセンサーの成功確率とは独立した位置の条件です。移動区間を分割し、相対移動が指定距離を横切る時刻も計算するため、通常の記録間隔より短い通過でも判定します。動く目的へ向かう移動の精度は計算刻みに依存するため、曲がる目標などでは刻みを細かくして比較してください。

例は「サンプルを開く」→「航路切替・目標への接近」。航路Aで探知→航路B→移動中の相手ユニットへ向かう→水平300m以内で終了、を設定しています。

データ定義：

```json
{
  "routes": [
    {"id":"a", "name":"航路A", "points":[{"x":0,"y":0,"z":0},{"x":1000,"y":0,"z":0}], "mode":"once"},
    {"id":"b", "name":"航路B", "points":[{"x":0,"y":500,"z":0},{"x":1000,"y":500,"z":0}], "mode":"once"}
  ],
  "destinations": [
    {"id":"x", "name":"地点X", "kind":"point", "point":{"x":1000,"y":1000,"z":0}},
    {"id":"enemy", "name":"相手ユニット", "kind":"unit", "unitId":"target"}
  ]
}
```

状態は `{"id":"follow-b","kind":"follow","routeId":"b"}` または `{"id":"approach","kind":"move","destinationId":"enemy"}`。接近線は `{"from":"approach","to":"stop","when":"near","destinationId":"enemy","distance":300,"distanceMode":"horizontal"}`。共通イベントは `{"id":"near-enemy","event":"near","to":"stop","destinationId":"enemy","distance":300,"distanceMode":"absolute","once":false}`。

経路は最大128件、目的地は最大256件。IDは各種別内で一意の英数字・`_`・`-`、1～80文字、名前は1～120文字。経路は2～500点、`mode` は `once|loop|pingpong`（省略時once）。目的地の `kind` は `point|unit|received`、`point` はx/y/z、`unitId` は単体ユニットIDです。接近距離は0～1000000m、`distanceMode` は `horizontal|absolute`（JSON省略時absolute、UI新規作成時horizontal）。

`{"id":"received","name":"受信した目標位置","kind":"received"}` は受信した観測位置を参照します。移動状態では `{"id":"move","kind":"move","destinationId":"received","heightMode":"keep"}` と指定し、状態へ入った時点で目的地を固定します。未受信の場合は待機します。情報受信イベントを `once:false` にしてこの状態へ接続すると、受信ごとに移動先を更新します。位置情報のない通信は保存済みの位置を変更しません。同じ目標の古い観測情報で新しい位置を上書きしません。

`heightMode` は `keep|target`。省略時は地点が `target`、ユニット・受信位置が `keep` です。`keep` は移動開始時の高度・深度を維持します。地上・水上では従来どおり地形・海面へ補正します。接近条件の絶対距離は観測位置の高さを含み、水平距離は高さを無視します。

通信は目標ID・観測位置・観測時刻・元の観測者を送信時の情報として保持し、中継でも保持します。受信者は相手の現在座標を自動取得しません。定期報告は直近の成功したセンサー観測を送信します。移動に失敗して停止したユニットも通信を受信でき、有効な現在位置から別の状態へ遷移できます。無効ユニットは送受信・計算の対象外です。

## 計算と再生

編集後は記録が無効になり、「未計算」と表示されます。「計算」でWorker内で終了時刻まで計算し、完了してから再生できます。中止と失敗を未計算・完了から区別します。再生速度と時刻スライダーは記録を見るための操作です。巻き戻しでシミュレーションは再計算せず、航跡も同じ記録から生成します。

探知の試行は固定の計算刻みで行います。通信受信、準備完了、到着、成功条件の期限は、刻みの間にあってもその時刻で処理します。記録は通常間隔に加え、移動区間・状態・ノードが変わる時刻にも残します。フレーム間の位置は直線補間、状態とノードは直前の記録を使います。計算刻みを変更した際は、短い接触の見逃しについて刻みを細かくした結果と比較してください。

位置などをFloat32、ノードをUint16、状態をUint8で保持します。生の記録上限は128MiB、保存ファイル上限は256MiB、フレームは100001件までです。1000個＋2単体・1時間の試験では約79.2MiB、3602フレームになりました。これは記録配列の大きさで、ブラウザ全体の使用量ではありません。経由点・イベントが多いと通常間隔以上に増えます。現在は全体フレーム方式なので、個体ごとの変更区間だけを保存する圧縮は未実装です。

## 分析と統一パラメータ

分析では成功条件、比較変数、試行数、要求率、試行ごとのばらつきを設定します。対象と性能を別々に選びます。群の個数も通常の比較変数です。複数比較変数は全組合せ、一様・三角分布は試行ごとの抽出です。

パラメータ台帳は意味・単位・検証範囲・保存先を一つに結びます。State／Capacity／Extent／Rateに加え、確率・挙動・ミッションの項目を登録します。同じ値を別の属性オブジェクトへ二重保存しません。

現在扱える変数は、移動速度、探知距離・確率・取付高、被探知係数、通信距離・遅延・成功確率、群の個数、配置・個別経路の位置、周回の開始割合、航跡の水平／上下ずれ・変動間隔・出発遅れ・速度ばらつき、共有経路の位置・開始割合、間隔調整、タスクの準備時間、成功条件の期限です。能力を登録すれば物理作用まで自動実装されるわけではありません。燃料・電池・補給・交戦などの状態更新は今後の実装です。

共有経路を使う担当者の古い位置・配置幅・個別の周回開始値は分析候補から除外します。代わりにタスクを対象とする変数を選びます。群の個数0では担当が消えても計算モデルや判定刻みは変わりません。削除時は分析参照も整理します。無効な参照は実行前に拒否します。

乱数シードと試行番号で抽出・航跡・接触・通信を再現します。同じ試行番号では能力比較に対応する乱数を共有します。行動により観測回数や配置が変化する比較で、結果の単調増加を一般に保証するものではありません。

図の横軸は数値に応じた間隔で、線形／対数を選べます。個数0は対数図から除外されますが表には残ります。成功率とWilsonの両側95%信頼区間、未成立率、成功時刻の中央値を表示します。要求率は比較の目安です。分析は詳細位置を保存せず、一つの試行を「再現」したときにその試行だけを計算・記録します。

### 状態への初回到達を計測する

地図の「配置編集」「地形・領域編集」と同じツールバーに「分析」があります。「計測する結果」で「挙動の状態への初回到達」を選び、「対象タスク」と状態を指定します。ノードの編集欄・右クリックの「計測対象にする」でも、現在の担当タスクと選択状態を設定できます。ノード上には「計測対象」の印が付きます。

状態Aから到着条件で状態Bへ遷移する場合、状態Bへの初回到達を測ります。状態の処理終了を成功とはしません。成立条件は担当のうち一つ／有効な担当すべて／指定数です。担当に群を含む場合は生成された個体ごとに数えます。初期状態は時刻0、退出・再入場は最初の到達を保持します。期限後の到達は期限内到達数に含めません。担当が0個なら「すべて」でも未成立とします。

分析の表は成立率・成功試行の初回成立時刻中央値・平均到達数を表示します。成立時刻の分布は、全試行を分母とする累積到達率です。指定人数の場合はその人数がそろった時刻、全員の場合は最後の担当が初めて入った時刻を使います。個々の初回到達時刻も分析結果・再生記録に保存します。タスク・対象状態を削除すると計測条件を解除し、Undoで一緒に戻せます。タスクの挙動を変更した場合も選択を解除します。

### 編集用ユニットを計算から外す

単体設定の「計算に使用する」を外す、または地図で右クリックして「計算から外す（無効化）」を選びます。地図・一覧には無効と分かる表示で残り、配置・能力・経路・担当タスクを編集・保存できます。移動計算、探知する側とされる側、送受信、状態到達・旧探知／到着条件の人数、詳細記録フレームから除外します。再生中も編集用の初期位置に表示します。有効化すると再計算が必要になります。無効なユニットを移動目的・受信先にした処理は、対象不在として扱います。

単体と群の有効／無効は独立します。無効なひな形を選んで群を作っても、その群は有効です。群の個体を選んで同じ切り替えを行うと、群全体を変更します。保存フィールドは単体の `enabled` と群の `enabled`（省略時は有効）です。群の `template.enabled` は生成個体へ引き継ぎません。

状態計測は `mission: {type:"state", assignmentId, nodeId, join:"any"|"all"|"count", requiredCount?, deadline}` です。`requiredCount` は `count` 時に1～2000、時刻は秒です。個数0の比較試行では対象タスクを空の担当のまま保持し、計測結果を未成立として保存します。

## 地形・探知とサンプル

地形の正本は `terrain: {columns, rows, spacing, spacingY?, origin:{x,y}, seaLevel, elevations:[...]}`。標高配列は南側の行から順に、各行は西から東へ並べます。縦横2～513格子、間隔1～10000m、標高-12000～10000mで、格子間は双線形補間です。海面の高さは別の値で、海底は負の標高などとして同じ配列に保存します。表示はこの格子から作る三角形メッシュで、高さ表示倍率はデータを変えません。`spacing`はX方向の間隔、`spacingY`はY方向の間隔です。`spacingY`を省略した旧データはX・Y共通の間隔を使います。

地図の「地形・領域編集」でブラシを選び、地図をクリック・ドラッグします。高くする／低くする、指定標高にそろえる、周囲の格子へ平滑化する操作があります。半径・変化量・目標標高を指定し、円内に距離で弱くなる重みを掛けます。海底を見やすくするため編集中は海面表示を一時的に隠し、終了すると元の表示へ戻します。Space＋ドラッグで3D回転／真上の平行移動、右／中ドラッグで平行移動、ホイールで拡大縮小できます。右クリックでその地点の編集中の標高を取得し、「指定標高にそろえる」へ切り替えます。小数・海面下の標高も取得でき、高さ表示倍率には影響されません。Shift＋右クリック、またはメニューキー／Shift＋F10でブラシ・Undo/Redo・適用・取消を選べます。一筆や領域サイズ変更ごとのUndo/Redo、取消・Escで全体取消、適用後の全体Undo/Redoを使えます。適用すると時刻を0へ戻し、記録・分析は再計算が必要になります。保存・再読込には通常のシナリオ保存を使います。

「指定標高にそろえる」と「平滑化」では独立した「強度（%）」（初期値50%）を使います。指定標高の場合は現在の標高と目標の差に強度を掛け、同じ場所を繰り返し塗ると徐々に近づきます。20%ならブラシ中心で差の20%を1回ごとに変えます。下げる方向にも使えます。0%は変更なし、100%は中心を指定標高にそろえ、ブラシの端は従来どおり弱くなります。平滑化では近傍格子の平均との差に同じ強度を掛けます。「高くする／低くする」のm単位の変化量は別に保持します。標高を取得するだけでは地形を書き換えません。

「領域サイズ（幅 × 高さ）」を開き、幅・高さをkm単位で入力します。「サイズをプレビュー」で確認し、「適用」で確定します。適用だけでも入力したサイズを反映します。グリッド数は読込中の地形の列数・行数に固定し、縦横の間隔を独立して変更します。座標原点・ユニット・経路・目的地の座標は変えません。既存地形を双線形補間し、追加領域は旧地形の端の標高で埋めます。縮小で現在の領域内にあるユニット・経由点・名前付き経路・目的地・担当設定が外へ出る場合は、対象名を表示して変更を止めます。各間隔1～10000mの範囲内で指定し、取消とUndo/Redoでサイズと標高を一緒に戻せます。

地形編集後にユニット・経路が新しい地形へ適合しない場合、ユニットを自動移動せず地形制約停止として表示します。センサー・通信の地形遮蔽、ユニット移動の判定はいずれも変更後の格子を使います。見通しと経路の判定は格子間隔の1/4以下（最大125m）に分割する近似です。細い地形や際どい接触の厳密な連続衝突判定は行いません。

座標はローカルのx/y/z、距離m、時間s。地上は標高へ投影、水上は海面、水中と空中は深度・高度を使います。地形格子と経路を照合し、制約違反を理由付きで停止します。自動探索・再配置はしません。見通しは地形による直線遮蔽の近似で、海洋音波伝搬ではありません。

探知は最大距離内で試行し、距離減衰・被探知係数・時間幅から確率を計算します。センサーの対象領域と陣営を参照します。成功条件の観測側・対象側を変えても、物理的な探知や条件付き行動そのものを切り替えません。評価は指定状態への初回到達、期限内の対象一つ／すべての初回探知、または指定単体の到着一つ／すべてです。継続追尾・接触品質・通信ネットワーク最適化は未実装です。

起動サンプルは二島間を通る潜水艦と、島を周回するUUVです。個数4／8／16／32×距離0.75／1.5／2.5km、12条件×50試行。その他は上部の「サンプル」から選びます。7サンプルをversion 3へ更新しています。地形と性能はすべて架空で、実装確認用です。

## 保存形式と旧版からの移行

| ファイル | 形式 | 内容 |
|---|---|---|
| シナリオ | `version: 3` | 地形、能力、経路、挙動、タスク、成功条件、分析条件、記録設定 |
| 分析結果 | `type: SimSim-analysis`, `version: 5` | 元定義・条件・各試行・抽出値・モデル識別子 |
| 再生記録 | `type: SimSim-recording`, `version: 2` | 元定義・対象ID・ノード名・配列・評価とイベント |

計算モデル識別子は `trigger-behavior-v3`。JSON内容を `.txt` で保存します。以前の `.jsn` と `.json` の手動読込も可能です。中身は従来と同じJSONで、既存ファイルの拡張子を `.txt` に変えるだけでも読み込めます。記録読込では配列長・時刻・有限値・状態・担当ノード・イベント参照と位置を検証し、分析読込では抽出値とシード／分布の一致、件数と成否を検証します。分析結果の読込時に試行を再計算するわけではありません。

旧シナリオの `behavior.hold/preparation/rules` は読込専用の変換境界で処理し、挙動とタスクへ変換します。同じ条件に複数の旧ルールを置くなど、意味を保って変換できないケースは拒否します。旧ルールと既存タスクの重複も拒否します。変換後に保存するとversion 3です。旧分析結果・旧再生記録は旧版で開き、必要なら元シナリオ定義を新版で読み込んで再計算してください。旧計算値を新版の計算値と同一視しません。

名前付き経路は `routes` が正本です。旧共有経路はタスク、旧個別経路はユニット／群のひな型が正本で、編集コマンドが担当値も含めて対象を解決します。旧経路を名前付き経路へ移す操作は互換性を保ちながら行えます。

## 経路の検査・自動生成と編集

ユニット設定または地図右クリックの「経路の検査・自動生成」で、現在の経路を編集します。共有経路は挙動編集で経路を開き、折りたたみの「地形の検査・自動生成」から同じ機能を使います。

1. 領域・生成するz座標・追加の余裕を指定します。水中・空中は固定高度で迂回し、水上・地上は海面・地表に合わせます。
2. 必須地点の先頭を出発点、末尾を目的地にします。途中の点も必ず通ります。周回では3点以上指定し、最後から最初へも安全につなぎます。
3. 「地形を避けて生成」を押し、上の座標欄で確認・修正して保存します。生成に失敗した場合は既存の座標を保持します。
4. 保存後は通常の地図ドラッグ、経由点追加・削除、数値入力で編集できます。元に戻すにも対応します。

「現在の経路を検査」は各線分の地形条件と追加の余裕を確認します。点だけを検査せず、双線形補間した標高のセル内の極値まで確認します。地図下の「経路を検査」は一覧を表示し、配置編集中は問題のある区間を赤線で示します。閉じた経路の最後から最初への線分も含みます。地形編集・経由点変更後は再検査します。不正な手編集は警告し、修正できるよう保存・読込を許可します。

名前付き経路には `points` か `generate` のどちらか一方を指定します。`generate` は領域 `domain`、水中／空中で必須の固定z座標 `height`、追加余裕 `clearance`（既定0m）、必須地点 `via`（2～100点、周回3点以上）を持ちます。`mode` は `once`・`loop`・`pingpong`。協調して周回する `patrol` の生成要求は `loop` にします。

読み込み時に生成し、保存される経路は通常の `points` と検査用の `navigation: {domain, clearance}` になります。再読込や地形変更で手編集を自動上書きしません。非常に細い海峡は探索格子で見つからない場合があります。絶対的な最短経路、旋回半径、燃料や他ユニットとの衝突は対象外です。

固定経路の検査と生成です。未来のイベント時点から経路への接続、移動するユニット／受信座標への直線移動、航跡の揺らぎは、実際に計算して確認してください。

## 複数計測点と計算履歴（2026-10-06追加）

分析内の「追加の計測点・段階別分析」から最大12点の状態到達条件を登録できます。トップレベルの`measurements`配列に保存し、各点のID・名前・タスク・状態・人数条件・期限を持ちます。`previousId`は先に登録した計測点を所要時間の起点にします。追加点はミッション全体の成功条件と独立して評価します。到達率・成立時刻・起点成立後の到達率・所要時間の中央値・未達再生を比較条件ごとに表示します。担当0人は未達、初期状態は0秒、初回到達を保持します。

計測点がある分析はシナリオの終了時刻まで計算します。段階間の所要時間は人数条件の成立時刻どうしの差で、同じ個体の移動時間とは限りません。順序逆転は件数を表示し、所要時間から除外します。ノード・タスクの削除時に参照を整理し、Undoで戻せます。

地図下の「計算履歴」は全期間の状態・探知・送受信などをユニット別に表示し、クリックで記録時刻へ移動します。一覧は30個まで、個体を選ぶと残りも確認できます。詳細イベント一覧は現在時刻までの末尾200件です。密な点は表示位置ごとに集約し、記録自体は保持します。

画面は「タスク一覧 | ユニット一覧 | 3D表示 | ユニット編集」の4ペインです。タスク選択は担当ユニットを一覧・地図で強調し、ユニット選択は一覧・地図・編集対象と担当タスクを連動させます。タスク編集は一覧の「編集」から開きます。名前・現在状態はユニット一覧に集約し、地図上の名前ラベルと専用ラベル欄を撤去しました。選択中・ホバー中・フォーカス中の対象には一覧との対応線を表示します（「表示」から切替可能）。境界のドラッグまたは左右矢印で幅を調整でき、タスク一覧は折りたたみできます。表示設定はブラウザに保存します。
