# 運用案比較

分析の種類「運用案の比較（配置・経路・挙動）」で現在の設定を名前付きで保存し、地図やノードを編集して別案を保存する。保存済み案を選んだ場合は更新。「地図に戻して編集」で案の設定を読み戻せる。最大8案・各案2000試行・合計10000試行、実行には2案以上が必要。

`analysis.mode = "plans"`、`analysis.plans = {metric, baselineId, items:[{id,name,operation}]}`。operationはunits/groups/behaviors/behaviorAssignments/routes/destinationsの6配列。シナリオ全体やanalysisを再帰保存しない。シナリオの保存に案を含め、Undo/Redoを使える。

地形、期間、成功条件、追加計測点、シード、開始試行番号、記録刻み、試行数、要求成功率、ばらつきは実行時のシナリオを共通適用。factors/groupId/countsは実行に使用しない。共通のばらつき対象は各案に存在する必要があり、抽出値は案の設定値に上書きされる。異なる成功条件での比較は行わない。保存後の運用設定編集は更新しない限り案へ反映されない。

基準を最初に計算し、同一試行番号の結果を対応付ける。乱数は既存のIDと用途によるハッシュストリーム。案名・並び順に依存せず、共通のIDを保持した変更で対応する乱数を共有する。新規ID・増減した要素・変更されたイベント時刻は完全な対応とはならない。同じ乱数条件は同じ探知・通信結果を意味しない。

成立率・計測点の率は全対応試行、時刻・段階間所要時間は両案に有効値のある対応試行のみで平均差を集計。未達・起点未達・逆順を時間0に置き換えない。表の基準・比較平均も対応試行の平均。欠測件数と初期配置不正の対応件数を示す。95%近似区間は感度分析と同じStudent tによる対応差の近似。1試行は区間なし、定数差は幅0。複数案を選別する際の多重比較補正は行っていない。成立率と時間の両方を確認する。

各案の絶対成立率（Wilson区間）と成功試行の時刻中央値、段階別集計、累積成立時刻分布も従来の結果画面で確認できる。対応再生と未達再生は共通条件＋案＋同一試行番号を再構築し、同じ実行モデルで記録を作る。

結果はSimSim-plans/version 1、現行RECORD_MODEL。sourceに案と共通条件、rowsに完了試行を保存。読込時に案ごとのシナリオを構築し、試行ID・抽出値・成否・状態・追加計測結果を従来の厳格検証で確認し、集計を再構築。基準試行がない比較結果や条件重複は拒否。途中結果も完了試行のみ保存・読込できる。

成功条件の有効トグルは廃止。分析編集・実行で画面の条件を必ずmissionへ保存。通常計算用にmissionのない旧シナリオを読み込むことは可能で、読み込んだだけでは自動付与しない。

検証：`tests/plans.test.mjs`（複合変更・共通抽出・並び順・欠測・再現・部分結果・改ざん・上限）、`tests/plans-browser.mjs`（成功条件なしからの分析・案保存と編集・Undo・Worker・対応再生・読込・基準切替・サンプル・画面幅）。通常版とportable版で同じブラウザ検証を実行。
