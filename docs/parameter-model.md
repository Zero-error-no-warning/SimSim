# 統一パラメータとモンテカルロ（0.4.1）

Entityの能力をState・Capacity・Extent・Rateに整理する考え方を基に、`src/parameters.js`を共通のパラメータ定義表とする。定義表に意味上のキー、表示名、単位、範囲、整数条件、対象範囲、現在のエンジンへの接続先を置く。UI、検証、比較、抽出、再現が同じ定義を使う。

既存の`speed`、`sensor.range`等が値の保存先であり、同じ値を別のEntityオブジェクトへ二重保存しない。将来のデータ構造移行時もこの接続部分で対応する。兵器種ごとの根本クラスを追加する仕組みではない。

| 分類 | 今回の実装 |
| --- | --- |
| State | 配置・経路の中心x/y、高度・深度z |
| Capacity | 群の個数（群全体の数量設定） |
| Extent | 探知距離、被探知係数、センサー取付高、配置幅x/y |
| Rate | 移動速度 |
| Interaction | 接触領域内での距離0・1分の探知確率 |
| Motion | 個体／群共通の水平ずれ、上下ずれ、変動間隔、出発遅れ、個体速度のばらつき |
| Mission | 成功条件の期限 |

確率・航跡ノイズ・ミッション期限を無理に4分類へ入れず、能力プリミティブと作用条件・シミュレーション設定を同じ登録方式で扱う。Signatureは現行の無次元被探知係数であり、物理的な半径ではない。探知距離は球状の最大試行範囲で、領域内で常に探知する保証ではない。

## UIと対象

「探知・分析」で「比較変数を追加」を押し、対象（ユニット・群・シナリオ）と属性を別々のリストから選ぶ。属性リストにはその対象で使用できる項目だけを表示する。群の個数も「対象: 群」「属性: 群の個数」として同じ欄で設定する。個数を固定する場合は個数の比較変数を追加しない。ばらつきの設定も同じ二段階選択を使う。

比較値はすべての組合せを計算する。例: 個数`[100, 300]` × 探知距離`[300, 600, 900] m`なら6条件。比較変数は最大9個、ばらつきは最大8個、比較値は各最大12個、全組合せは最大24条件、条件数×試行数は10000以下。単体＋群の2000個上限も維持する。同じ対象の同じ変数を比較とばらつきの両方へ指定できない。

画面はkm・min・%等に変換するが、ファイル内の値は既存のSI規約に従うm・s・確率（0～1）。変数の上下限を検証し、誤った入力はエラーとして元の設定を保持する。地形外や海底との衝突は、従来どおり制約違反として試行に残す。

群のひな型への抽出は**群全体で共通の能力値**となる。各個体の速度差・出発遅れ・航跡の差は`motion`設定で表現する。個体ごとの探知距離や被探知係数の独立抽出は未実装。

## 分布と再現

- 一様分布: 最小値～最大値から抽出する。
- 三角分布: 最小値、最頻値、最大値を使う。端の最頻値や最小=最大も許可する。
- 個数を抽出する場合は連続抽出値を四捨五入する。端の整数が中間の整数より低確率になり得るため、離散一様分布ではない。
- 分布間の抽出は独立。相関行列や共通の潜在変数の指定は未実装。

抽出用のストリーム名は`parameter-sample-v1`。シード・試行番号・対象ID・意味上の変数キーから決まる。同じ試行では比較値、比較条件の並び、他の抽出変数の追加・削除によって抽出値が変わらない。配置・航跡・探知の乱数ストリームとは分ける。

配置のx/y/zを変更すると、初期位置だけでなく経由点も同じ差分で平行移動する。群ではその後に個体の配置オフセットを適用する。個数0の群への他の属性変更も行った後、群を取り除く。

試行の「再現」は分析元へその条件の比較値と同じ抽出値を適用した定義を読み込む。分布から抽出した値を画面に表示し、成立時刻またはその試行の期限へ移動する。再生中に値を再抽出しない。「分析元のシナリオに戻す」で分析前の定義へ戻る。

## データ例

```json
"analysis": {
  "trials": 100, "step": 10, "requiredRate": 0.95,
  "factors": [
    {"target": "group:observers", "parameter": "capacity.population", "values": [0, 100, 300]},
    {"target": "group:observers", "parameter": "extent.sense.radius", "values": [300, 600]}
  ],
  "uncertainties": [
    {"target": "unit:transit-target", "parameter": "rate.movement.speed", "distribution": "uniform", "min": 10, "max": 24},
    {"target": "unit:transit-target", "parameter": "extent.signature.coefficient", "distribution": "triangular", "min": 0.2, "mode": 1, "max": 2}
  ]
}
```

対象は`unit:<id>`、`group:<id>`、`scenario`。個数を固定する場合は`capacity.population`の比較変数を追加しない。新規・編集後の分析設定には`groupId`・`counts`を保存しない。旧形式の`groupId`・`counts`は読み込み時に同じ比較変数として表示し、編集・分析実行時に通常の`factors`へ変換する。旧設定の条件ID・シード・抽出値は維持する。結果ファイル読み込み時は元の設定を保持するため、旧version 1の保存結果も引き続き復元できる。

結果ファイルは`SimSim-analysis` version 2。モデル名`range-hazard-v1`、各条件の設定・ID、各試行の抽出値を保存する。読み込み時には条件IDを元の設定から再構成し、抽出値がシード・分布と一致するか確認する。率とWilson区間は試行結果から再集計する。探知結果そのものの再計算による検証は行わない。旧version 1の個数比較結果も読み込み・version 2への保存が可能。

## 散布図

横軸を比較変数から選び、実際の数値に比例する線形軸、または比に対応する対数軸で表示する。縦軸は成功率0～100%で固定。点が成功率、縦線が両側95%Wilson区間、橙色の線が要求率。

対数軸では0以下の条件を**図だけから除外**し、件数を表示する。表・集計・保存には残す。他の比較変数の設定が同じ条件は同じ色で示し、凡例にその設定を表示する。点のツールチップにも条件と区間を載せる。同じ横軸値・成功率の点は重なるため、各条件の正確な結果は表で確認する。

## 次の拡張

共通のState・Capacity・Rate更新処理、Extentのshape/model、Interactionの条件・確率・State変化を加えることで、電池・燃料・通信・補給へ広げられる。ただし新しいパラメータを定義するだけでは作用は生じない。状態の更新、対象領域、遮蔽、資源保存、成功判定への接続を実装・検証してから選択肢へ登録する。今回、電池・燃料・通信・攻撃・充電・修理の計算は追加していない。
