## 01 最初に試す操作

[操作01-01] サンプルを計算して再生する
1. 配信されたSimSimをPCブラウザで開きます。
2. 上部の「サンプルを開く…」から「島間通過・周回UUV」を選びます。起動時にもこのサンプルが開きます。
3. 地図下の「計算」を押します。「未計算」が計算中の表示に変わります。
4. 「記録済み」が表示されてから「▶ 再生」を押します。
5. 時刻スライダーで前後の時刻へ移動し、左のユニット一覧か地図で対象を選びます。
6. 右側の「再生中の状態」や、地図下の「計算履歴」で移動・探知・通信・状態遷移を確認します。
7. 設定を変えたら、もう一度「計算」を押します。

再生は計算済みの記録を見る操作です。スライダーを戻しても新しい乱数で計算し直しません。
右側の「速度（km/h）」はユニットの移動速度、再生操作の「速度 ×60」などは記録の再生速度です。両者は別です。

[操作01-02] 変更した設定を残す
上部の「.txtを保存」を押し、ダウンロードされたシナリオTXTを保存します。ブラウザを閉じても現在の編集内容が自動で永続保存される、とは扱わないでください。
計算済みの動きを残す場合は「記録保存」を使います。シナリオ保存と記録保存の違いは第03章です。

## 02 画面の場所と用語

[画面02-01] 画面の案内
ロゴ横のバージョンは画面版の日付と更新番号（例：v2026.10.06.17）です。更新時に読み込みURLの版情報と一緒に更新します。シナリオ・記録・分析ファイルの形式のversionとは別です。
| 場所 | 主な操作 |
|---|---|
| 上部 | 新規、サンプルを開く、開く、.txtを保存、ヘルプ |
| 左端・タスク一覧 | シナリオ名、タスクの選択・追加・編集 |
| 左から2列目・ユニット一覧 | ユニットの選択・追加、現在状態、群の作成、元に戻す・やり直す |
| 地図上のツールバー | 配置編集、地形・領域編集、分析、3D、真上、表示 |
| 地図 | ユニットの選択・配置、経由点編集、右クリックメニュー |
| 右側 | 選択したユニットの能力・経路・担当タスク・再生中の状態 |
| 地図下 | 計算履歴、計算設定・乱数シード、計算・再生、時刻スライダー、経路を検査 |

「経路・初期位置」「センサー能力」「通信能力」などは折りたたみ欄です。見出しをクリックして開いてください。下の項目が見えない場合は右側の設定領域をスクロールします。
「表示」には経路・航跡・一覧との対応線・探知範囲・海面の表示切替と高さ表示倍率があります。高さ表示倍率は見た目だけを変え、実際の標高や距離を変えません。
現在の画面には旧版の「操作」プルダウンや「行動・通信」専用画面はありません。

[用語02-02] ユニット・群・挙動・タスク
| 用語 | 意味 | 例 |
|---|---|---|
| ユニット | 一つの機体・船・地上の対象。位置、速度、センサー、通信などを持つ | UAV、UUV、艦船、基地 |
| 群 | 同じひな型から作った複数のユニット | UUVを8個作る |
| 挙動 | 状態と条件をつないだ、再利用できる動作の設計 | 周回し、探知したら報告する |
| タスク | 誰がどの挙動を、どの担当値・共有設定で実行するか | 群Aに監視挙動と航路Aを割り当てる |
| 状態ノード | その状態中にする処理 | 経路を進む、情報を待つ |
| イベントノード | 現在の処理へ割り込むきっかけと行き先 | 情報受信で移動状態へ入る |
| 遷移線 | 始点の状態で条件が成立したとき、次の状態へ移る接続 | 移動から到着条件で終了へ |
| 名前付き経路 | シナリオ内で共有して選択できる座標列 | 航路A、島の南側の迂回経路 |
| 目的地 | 移動・接近判定の対象 | 帰投地点、単体ユニット、受信位置 |
| 計測条件 | 何がいつまでに成立したら成功と数えるか | 指定状態に担当者が到達した |

単体または群に同時に割り当てられるタスクは一つです。同じ挙動を複数のタスクで再利用できます。群とタスクは別のものです。
タスク未割当のユニットも、個別に設定した経路を進みます。必ずタスクを作らないと移動できないわけではありません。

## 03 新規作成・ファイルを開く・保存

[操作03-01] 新規シナリオを作る
1. 必要なら現在の内容を「.txtを保存」で保存します。
2. 上部の「新規」を押します。
3. 現在の地形を残したまま、ユニット・群・挙動・タスク・経路・目的地・計測条件・分析設定を空にします。
4. 地図を右クリックしてユニットを配置するか、第04章の追加操作へ進みます。

「新規」は地形を平坦にするボタンではありません。直後なら「元に戻す」で前のシナリオへ戻せます。

[操作03-02] ファイルを開く
1. 上部の「開く」を押します。
2. シナリオ、再生記録、または分析結果のTXTを選びます。
3. 保存していない変更の確認が出たら、残す必要がある内容を先に保存します。
4. 読み込みエラーが出た場合は内容を確認します。数字のversionを手で変更して通すことを対処として案内しません。

[用語03-03] 三種類の保存ファイル
| 保存ボタン | 保存する内容 | 読み込み後 |
|---|---|---|
| 上部の「.txtを保存」 | 地形・配置・能力・経路・挙動・タスク・計測・分析設定 | 時刻0の定義として開く。必要なら計算する |
| 計算操作の「記録保存」 | 計算済みの位置・状態・イベントと元の定義 | 記録を再計算せず再生できる |
| 分析画面の「結果を.txtで保存」 | 分析元の定義・比較条件・各試行・結果 | 保存済みの分析表を再計算せず開く |

いずれも上部の「開く」から読み込みます。拡張子は同じTXTでも、中身の用途は異なります。シナリオ保存だけでは計算済みの記録全体や分析結果は保存しません。
保存形式はTXTの中にJSONを格納します。利用者が通常の操作でJSONを編集する必要はありません。旧JSN・JSONも手動読込の対象です。
現行のシナリオ定義はversion 3、再生記録はversion 2、分析結果はversion 5です。ファイル種類ごとに番号が違うため、全てを同じ番号に変更してはいけません。
旧版のシナリオは対応できる範囲で変換します。旧版の分析結果・再生記録は、対応する旧版で開きます。

[操作03-04] 編集の確定と取消
ユニットの通常の数値欄は、変更後にTabなどで入力欄を離れると反映します。入力中の数字だけを見て確定済みと判断しないでください。
群・地形・タスクと挙動の編集は「適用」でシナリオへ確定します。「取消」では編集を反映しません。
挙動の中で経路・目的地・担当値を「保存」しても、まずは挙動編集の下書きへ保存されます。最後に「タスクと挙動」画面の「適用」が必要です。その後、ファイルにも残したい場合は上部の「.txtを保存」を押します。
通常の編集、挙動図の編集中、地形の編集中にはそれぞれのUndo/Redoがあります。ファイルを開き直した後まで編集履歴を持ち越すものではありません。

## 04 地図操作とユニットの配置

[操作04-01] 単体ユニットを追加する
1. 地図の空白を右クリックします。
2. 「水中ユニットを配置」「水上ユニットを配置」「航空ユニットを配置」「地上ユニットを配置」から選びます。
3. 地図上の置きたい場所をクリックして確定します。Escで配置を取り消します。
4. 右側で名称・陣営・運用・速度を設定します。

左側の領域選択と「＋ 追加」からも配置を開始できます。地形に適合しない場所には配置できません。水中を置く場合は島や浅瀬から離れた場所を選び、深度も確認します。

[操作04-02] 選択・移動・複製・削除
・地図の記号か左側のユニット一覧をクリックして選択します。
・「配置編集」を有効にして記号をドラッグすると、通常はユニットとその経路全体を移動します。
・初期状態が共有経路を使う場合、編集先は共有経路になります。複数の担当へ影響することがあります。
・初期状態の経路への入り方が「最短地点から」の場合、記号の移動は初期位置を変更し、名前付き経路は移動しません。
・番号付き経由点は個別にドラッグして編集します。選択してDeleteで削除できます。
・対象を右クリックして「複製して配置」を選ぶと、設定を複製して新しい位置へ置けます。担当タスクも引き継ぐ場合があります。
・ユニットを削除する場合は選択して「削除」または右クリックの削除を使います。報告先や目的地として参照中の場合は先に参照先を変えます。
・群の一個体をドラッグした場合は、群全体に対する編集です。

[操作04-03] 視点を動かす
| 操作 | 3D | 真上 |
|---|---|---|
| Space＋左ドラッグ | 回転 | 平行移動 |
| Shift＋Space＋左ドラッグ | 平行移動 | 平行移動 |
| 右／中ボタンのドラッグ | 平行移動 | 平行移動 |
| ホイール | 拡大・縮小 | 拡大・縮小 |
| F | 選択した対象へ移動 | 選択した対象へ移動 |

Spaceを押しながらの視点操作中は、配置や地形を編集しません。右クリックは押して離すとメニュー、ドラッグすると視点移動です。地形編集中の右クリックは第06章のスポイトになります。
見失った場合は地図を右クリックし、「全体を表示」を使います。3Dと真上は地図上部のボタンで切り替えます。

## 05 ユニットの能力・群・無効化

[設定05-01] 単体ユニットの基本設定
右側で名称・領域・陣営・有人／無人・速度を設定します。有人／無人の切替だけで別の知能・判断モデルが自動追加されるわけではありません。
「経路・初期位置」のx/yはkmです。水中ユニットの「深度（海面下 m）」には深度100mなら正の100を入力します。経路作成画面で使うz座標の-100とは表示方法が違います。
地上の高さは地表、水上の高さは海面に自動で合わせます。空中・水中は高さの条件を満たす必要があります。

[設定05-02] センサー能力
1. 「センサー能力」を開き、「探知センサーを使用」を有効にします。
2. 「最大距離（km）」と「距離0で1分の探知確率（%）」を設定します。
3. 対象にする領域（地上・水上・水中・空中）を選びます。
4. 必要なら「地形による遮蔽を判定」と「センサーの取付高」を設定します。
5. 対象側の「被探知係数」も確認します。0は探知不能、1が基準です。

表示される確率は、一回の計算刻みや最大距離での成功率そのものではありません。距離・被探知係数・計算刻みが影響します。センサー設定に加え、その状態ノードの「この動作中にセンサーを使用」が必要です。「終了」状態では探知しません。

[設定05-03] 通信能力
「通信能力」の「通信を使用」を有効にし、最大距離・遅延・1回の成功確率・地形遮蔽を設定します。
通信能力を有効にしただけでは自動送信しません。挙動に「報告」状態を作り、報告先を指定します。位置情報を送るには、センサーでの観測や引き継いだ受信情報が必要です。
送信失敗の確認は第16章のFAQ-06です。

[操作05-04] 群を作る
1. ひな型にする単体ユニットを作り、能力・初期位置・経路を設定します。
2. その単体を選び、左側の「＋ 選択ユニットから群を作る」または右クリックの「この設定から群を作成」を使います。
3. 群の名前・ひな型・個数を設定します。
4. 個別配置を使う場合は、配置方式とx/yの配置幅をkmで指定します。
5. 必要なら水平／上下のずれ・出発遅れ・速度のばらつきを設定します。
6. 周回経路では、全個体が同じ位置／均等に分散／ランダムに分散から出発位置を選べます。
7. 「適用」で確定します。

ひな型の設定は群へコピーします。元の単体を後から変更しても、群の設定が自動追従するものではありません。群を変える場合は個体を選んで「この群を編集」を使います。生成された個体の数値属性は直接編集せず、群のひな型を編集します。
共有経路を使う場合、古い個別配置幅を変えても狙った配置にならないことがあります。周回の分散は共有経路・タスクの出発割合や間隔設定で確認してください。
画面で群を作る際の個数は1以上です。0個との比較は分析の比較変数で指定します。

[操作05-05] ひな型を残して計算から外す
1. 使わない単体を選びます。
2. 右側の「計算に使用する」のチェックを外します。または右クリックの「計算から外す（無効化）」を選びます。
3. 地図と一覧には残り、設定の編集・保存はできますが、移動・センサー・通信・計測・詳細記録の計算対象から外れます。
4. 作成済みの群は単体とは独立して有効です。群も止めたい場合は、群の個体を選んで同じ切替を行います。
5. 再び使うときは有効化し、計算し直します。

無効なユニットを報告先や移動目的にすると、実行時は対象不在として扱います。

## 06 地形編集と領域サイズ

[操作06-01] 地形を塗る
1. 地図上部の「地形・領域編集」を押します。
2. ブラシから「高くする」「低くする」「指定標高にそろえる」「平滑化」を選びます。
3. 半径と、そのブラシで使う変化量・標高・強度を設定します。
4. 地図をクリックまたは左ドラッグして塗ります。編集中は海底を見やすくするため海面表示を一時的に隠します。
5. 「↶ 戻す」「↷」で一筆ずつ戻す／やり直すことができます。
6. 「適用」でシナリオへ確定します。「取消」またはEscは、編集中の地形全体を元に戻します。
7. 適用後は「経路を検査」で確認し、計算し直します。

[設定06-02] ブラシの違い
| ブラシ | 主な設定 | 使い方 |
|---|---|---|
| 高くする／低くする | 一筆の変化量（m） | 地表・海底を指定量ずつ上下する |
| 指定標高にそろえる | 標高（m）、強度（%） | 現在の標高を目標に近づける |
| 平滑化 | 強度（%） | 近くの格子と急な差をならす |

「指定標高にそろえる」の強度20%は、ブラシ中心では目標との差の20%を一回で変更する意味です。繰り返し塗ると徐々に近づきます。上げる・下げるの両方向に使えます。100%でも円の端は弱くなります。
平滑化の強度と指定標高の強度は独立して保持します。高くする／低くするの変化量とは別です。

[操作06-03] 右クリックで標高を取得する（スポイト）
地形編集中に地点を右クリックすると、その地点の編集中の標高を取得し、ブラシを「指定標高にそろえる」へ切り替えます。取得だけでは地形を書き換えません。海底の負の標高や小数も取得できます。
地形の右クリック編集メニューを開きたい場合はShift＋右クリックを使います。右ドラッグは視点移動です。

[操作06-04] 領域サイズ・地形格子数を設定する
1. 「地形・領域編集」→「領域サイズ・地形格子数」を開きます。
2. 「東西幅（km）」「南北幅（km）」で領域の広さを指定します。
3. 「地形格子数（東西）」「地形格子数（南北）」で標高点の数を指定します。各2～513の整数です。セル数ではなく頂点数なので、東西33点なら32区間です。
4. 「設定後の格子間隔」を確認します。領域サイズを変えずに地形格子数を増やすと、細かく編集できます。例：東西幅8km・東西33点なら間隔250mです。
5. 「設定をプレビュー」で確認します。「↶ 戻す」「↷」で元の地形格子数と標高を復元できます。
6. 「適用」で確定します。プレビューを押さずに適用しても、入力したサイズ・地形格子数を反映します。「取消」で編集中の全変更を戻します。

変更後の標高点で既存地形を補間します。地形格子数を増やしても、元の粗い地形にない細部は復元されません。減らした場合や、地形格子数を保ったまま領域だけを拡大した場合は、小さな島などの細部が失われることがあります。数値を元に戻す操作は標高の復元ではないため、元へ戻す際はUndoまたは取消を使います。
各格子間隔は1～10000mです。座標原点・ユニット・経路・目的地は移動しません。拡張した領域は元の地形の端の標高で埋めます。縮小で現在の領域内の位置・経路・目的地が外へ出る場合は、対象名付きで変更を止めます。
サンプルを開くと、そのサンプルの領域サイズ・地形格子数になります。左端のシナリオ名の下に現在の地形格子数と格子間隔を表示します。粗い場合は地形格子数を増やしてから小さいブラシで編集してください。

[操作06-05] 島や海岸を作るときの順番
1. 大きなブラシで主な陸地の形を作ります。
2. 少し小さいブラシで岬・湾を加えます。
3. 平滑化で急な格子差をならします。
4. 海面付近と海底の深さを確認します。
5. 最後に経路を設定し、検査・計算します。

格子一つずつの細かな凸凹から島全体を作ろうとすると、不規則な海岸になりやすくなります。小さい島・海峡は格子の大きさで表現できる範囲に限られます。平滑化しただけで通行可能な海峡になるとは限りません。

## 07 経路の手動編集・検査・自動生成

[操作07-01] 個別経路を地図で作る
1. 対象のユニットを選び、「配置編集」を有効にします。
2. 右側の「経路・初期位置」を開きます。
3. 「＋ 地図で経由点を追加」を押すか、ユニットの右クリックから「経由点を追加」を選びます。
4. 地図を順番にクリックします。
5. 追加を終了するボタンまたはEscで終了します。
6. 番号付きの点をドラッグ、右側の座標欄を変更、または点を選択して削除して調整します。
7. 一度だけ／往復／周回を選び、検査・計算します。

周回は最後から最初へ戻る区間も含みます。円形の経路を作る場合は、ユニットを右クリックして「周回経路を作成（中心 → 半径）」を選び、中心・円周の順にクリックします。

[操作07-02] 名前付きの共有経路を作る
1. タスクと挙動の編集画面で「挙動のノード」を開きます。
2. 「経路を進む」または「協調して周回」の状態ノードを選びます。
3. 「＋ 新規経路」を押し、名前と繰り返し方法を設定します。
4. 「地図で経路を描く」で順にクリックし、2点以上作ってEscで経路編集へ戻ります。協調周回は3点以上にします。
5. 座標欄で修正できます。この欄は一行に「東西, 南北, 高度・深度」を全てmで入力します。
6. 「保存して選択」でノードへ設定し、最後にタスクと挙動の「適用」を押します。

図の「＋ 追加」→「経路を作る」から、ノードを選ばずに作ることもできます。経路名は、後から選択できるよう用途が分かる名前にします。同じ経路を使う複数のノード・タスクは、同じ経路の変更を共有します。

[操作07-03] 経路の地形検査
地図下の「経路を検査」を押すと、問題のある固定経路を一覧で確認できます。配置編集中は不正な区間を地図に赤線で表示します。「表示」の経路チェックが外れている場合は有効にします。
経路の編集画面では「地形の検査・自動生成」内の「現在の経路を検査」を使います。指定した領域と追加の余裕で確認します。
検査は点だけでなく線分の途中、周回の最後から最初への区間も確認します。地形を編集した後、点を動かした後にも確認します。
問題がある手作業の経路も、修正できるよう保存・読込自体は可能です。保存できたことを通行可能の証明にしないでください。

[操作07-04] 島・浅瀬を避ける経路を自動生成する
1. ユニットを選び、「経路・初期位置」→「経路の検査・自動生成」を開きます。右クリックからも開けます。
2. 共有経路の場合は、状態ノードの「経路を編集」を開き、「地形の検査・自動生成」を開きます。
3. 使用する領域を確認します。ユニットから開いた場合はそのユニットの領域を使います。
4. 空中・水中では「生成する高度・深度のz座標（m）」を指定します。海面0mで深度100mなら-100です。水上・地上は高さを海面・地表へ合わせます。
5. 「追加の余裕（m）」を指定します。新規経路では0、保存済みの経路では保存した値を使います。水中で20なら通常の海底から5mに20mを追加し、海底から25m以上離れる経路になります。海面側にも余裕が必要です。
6. 「生成の必須地点（m）」へ、一行に「東西, 南北」を入力します。最初が始点、最後が終点、中間の行は必ず通る経由地点です。
7. 「地形を避けて生成」を押します。
8. 生成された座標を確認し、必要なら編集します。
9. ユニット用の画面では「経路を保存」、共有経路の画面では「保存して選択」、その後に挙動の「適用」で確定します。
10. 地図で確認し、計算します。ファイルにも残すなら「.txtを保存」を押します。

始点・終点自体が島や浅瀬にあると生成できません。必須地点に通れない場所を指定しても、その地点を避けてくれるわけではありません。水中では深度が深すぎる場合、浅すぎる場合、余裕が大きすぎる場合も生成できません。
自動生成画面の初期の必須地点は、通常は現在の経路の始点・終点です。周回は途中の点も含む3点が候補になります。既存の全経由点を必須にしたい場合は「現在の経路の点を必須地点にする」を押します。
一度だけ／往復は2点以上、周回は異なる3点以上を指定します。周回は最後から最初の区間も生成します。

[操作07-05] 自動生成後に編集する
生成結果は通常の経路になります。座標欄、地図上の経由点ドラッグ、点の追加・削除で編集できます。元に戻す／やり直すにも対応します。
編集した経路を保存して開き直しても、手編集が自動生成で上書きされません。地形を変えても勝手には生成し直しません。検査して必要な場合に再生成します。
生成に失敗したときは前の座標を保持します。通れる地点・高さ・余裕へ変更して再実行してください。

[制約07-06] 自動生成と「最短地点から」の違い
自動生成は指定した地点間の固定経路を地形から迂回させます。
「最短地点から」は、現在位置から3次元の直線距離が近い既存経路の線分上の点へ合流する設定です。地形を避ける最短経路を探す意味ではありません。
未来のイベント時点から経路への合流、移動中のユニット・受信位置への直線移動は自動迂回しません。航跡のばらつきを加えた動きも別途計算して確認します。
細い海峡は探索格子で見つからない場合があります。生成できないことだけで、数学的に到達不能とは断定しません。旋回半径、燃料、他ユニットとの衝突回避や世界全体での厳密な最短経路は扱いません。

## 08 タスクと挙動を作る

[操作08-01] タスクへ担当者を割り当てる
1. 左側の「＋ タスク」、既存タスク、またはユニットの「担当タスクを設定」から「タスクと挙動」を開きます。
2. 「担当・共有設定」タブで、必要なら「＋ タスク」を押します。
3. タスク名、使用する挙動、担当する単体・群を指定します。複数選択はCtrl/Cmdを使います。
4. 報告で「タスクの報告先」を使う場合は、ここで報告先も設定します。
5. 共有周回では出発点・周回中の間隔・間隔の調整係数を設定します。
6. 「挙動のノード」タブで動作を確認・編集します。
7. 「適用」を押します。

新規タスクにはひな形の挙動や仮の共有経路が設定される場合があります。そのまま希望の航路になるとは限らないため、経路・目的地・報告先を確認してから適用・計算します。
タスクの担当が別タスクと重複した場合は適用できません。以前のタスクで担当を外してから設定します。
「出発準備時間」は準備時間を使う状態で参照する設定です。ここへ数字を入れただけで全ての出発に必ず待機が付く、と考えないでください。
共有周回の間隔は経路上の位相・進行を速度調整する簡易モデルです。機体間の3次元直線距離を常に厳密に一定にする制御ではありません。同じタスク・経路の担当者が同じ地点へ合流した場合も、順に進み出して間隔を広げます。同位置ではユニットIDで順序を決め、位置を飛ばさず速度を調整します。間隔調整をしない設定では分散させません。

[操作08-02] 挙動を作る・編集する
「挙動のノード」の「＋ 挙動」で新しい挙動を作り、挙動名を設定します。新規作成時にはひな形の状態が入るため、必要なノードを編集・削除・追加して目的の構成へ変更します。
同じ挙動を使う複数のタスクは、その図の変更を共有します。担当ごとに異なる動作図が必要なら「複製」で別の挙動を作ります。値だけを変える場合は第11章の担当値を使えます。
編集画面の「適用」で確定し、「取消」で下書きを破棄します。複数の下位画面で保存しても、最後の適用前はシナリオ全体への確定ではありません。

## 09 状態ノード・イベントノード・線の条件

[操作09-01] 状態ノードを作って種類を決める
1. 挙動図の空白を右クリックして「ここに状態ノードを作る」を選ぶか、「＋ 追加」→「状態ノードを作る」を使います。
2. 作成したノードをクリックします。
3. 右の「状態の種類」を選びます。
4. 選んだ種類に対応する経路・目的・待機秒数・報告先などを設定します。

| 状態の種類 | その状態中にすること | 次の状態へ使える主な条件 |
|---|---|---|
| 経路を進む | 指定経路を進む | 到着、対象を探知、情報受信、接近 |
| 協調して周回 | 経路を周回し間隔を調整する | 対象を探知、情報受信、接近 |
| 情報を待つ | 停止して情報などを待つ。センサー使用も設定できる | 情報受信、対象を探知、接近 |
| 報告 | 指定した相手へ通信を送る | 送信成功、送信失敗、接近 |
| 目的に向かって進む | 指定目的へ向かう | 到着、対象を探知、情報受信、接近 |
| 時間待ち | 状態へ入ってから指定秒数を待つ | 待機終了、対象を探知、情報受信、接近 |
| 終了 | 通常の処理を止める。探知は行わない | 状態間の出力線は作らない |

周回には終点へ到着する条件を期待しません。「終了」でも共通の情報受信・時間イベントが残っていれば、そこから再起動できます。永久停止にしたい場合は、その割り込み設計も確認します。

[操作09-02] 初期状態を決める
シーン開始ノードはありません。開始させたい状態を選び、「初期状態（シーン開始時にこの状態へ入る）」を有効にします。図に初期状態の印が付きます。
別の状態を初期状態にすると前の指定は外れます。初期状態を指定しない場合は、イベントが来るまで待機する挙動にできます。ただし初期状態もイベントノードもない挙動は適用できません。

[操作09-03] 状態をつないで条件を設定する
1. 接続元を右クリックして「ここから接続」を選びます。または「接続」ボタンを押します。
2. 接続元→接続先の順でノード本体を選びます。入力点・出力点はありません。
3. 作られた線または線のラベルをクリックします。
4. 右の「遷移する条件」を選びます。
5. 接近条件なら目的・距離・距離の種類も指定します。

線を作るだけでは条件設定は完了しません。同じ状態を接続元と接続先に選ぶと自己遷移です。接続開始の取消は背景クリックやEscで行えます。
一つの状態から同じ条件の線を複数出せません。ただし接近条件は目的・距離・距離の種類が異なる組合せを作れます。確率分岐や任意の条件式を入力する画面ではありません。
状態の種類を変えて既存条件が使えなくなると、線の条件は未設定に戻ります。線を選んで設定し直します。「終了」からの線は削除するか種類を変更します。

[操作09-04] 全状態へ割り込むイベントを作る
1. 「＋ 追加」→「イベントノードを作る」、または図の右クリックで作ります。
2. イベントノードをクリックし、右の「イベントの種類」を選びます。
3. イベントノードから接続先の状態へ線をつなぐか、「遷移先の状態」で指定します。
4. 「発火回数」を一度だけ／繰り返しから選びます。
5. 時間・接近なら必要な数値や目的を指定します。

イベントノードは紫、状態ノードは青です。イベントの線は共通の割り込み先を表し、状態同士の線のような別の遷移条件は付けません。状態ノードからイベントノードへはつなぎません。
共通イベントは現在の処理を中断して接続先へ入ります。同じイベントに対する状態間の線より優先します。全ての状態に同じ受信線を引く代わりに使えます。

| イベント | 一度だけ | 繰り返し |
|---|---|---|
| 情報受信 | 最初の通信受信 | 通信が届くたび |
| 時間経過 | シーン開始から指定秒数後 | シーン開始から指定秒数ごと |
| 対象探知 | 最初の成功した探知 | 同じ目標の新たな成功した再観測を含む |
| 指定距離まで近づく | 最初に範囲内になったとき | 範囲外に出てから再び範囲内に入ったとき |

発火回数は担当ユニットごとに管理します。繰り返しの対象探知は計算刻みでの新たな成功した観測に反応し、到着前の処理を何度も中断することがあります。初回だけの反応と繰り返し報告を区別します。
「時間経過」の基準はシーン開始です。「時間待ち」の待機秒数は、その状態へ入った時点が基準です。繰り返しの時間イベントで0秒は使えません。
共通の情報受信・対象探知イベントはそれぞれ挙動内に一つまでです。時間イベントは秒数が異なれば複数、接近イベントは条件の組合せが異なれば複数置けます。

[操作09-05] 図の編集を終える
ノードをドラッグして配置し、ホイールで拡大縮小、背景ドラッグやSpace＋ドラッグで表示を移動します。「全体表示」と右下のミニマップも使えます。
線・ノードは選択してDelete、または右クリックから削除できます。未設定ノード・条件未設定の線・遷移先のないイベントがある場合は「適用」できません。
「状態を完了した」という汎用の条件はありません。例えば移動状態から「到着」で次の状態へ移り、その次の状態に入ったことを計測します。

## 10 目的地・受信位置・接近条件

[操作10-01] 目的地を作る
1. 「目的に向かって進む」の状態を選びます。
2. 「＋ 新規目的地」で名前と「目的の種類」を選びます。
3. 地点は地図で指定するか、東西・南北をkm、高度・深度のz座標をmで入力します。
4. ユニットの現在位置なら対象の単体ユニットを選びます。群そのものや生成個体を選ぶ目的地ではありません。
5. 受信した目標位置なら固定座標を入力せず、その種類を選びます。
6. 「保存して選択」し、挙動の「適用」で確定します。

帰投地点も「地点」の目的地として作ります。図の「＋ 追加」→「目的地を作る」からも作成できます。名前付き目的地は複数ノードで共有します。

[用語10-02] 三種類の目的
| 目的の種類 | 移動先 | 注意 |
|---|---|---|
| 地点 | 設定した固定座標 | 帰投地点などに使う |
| ユニットの現在位置 | 計算上の相手の現在位置 | 探知・通信を待たずに現在位置を追う仮定 |
| 受信した目標位置 | 通信に含まれた観測座標 | 移動状態へ入った時に固定。報告一回で追尾を継続しない |

ユニット・受信位置を目的にすると、既定では移動開始時の高度・深度を維持します。地点は既定では目的地の高さに合わせます。「移動中の高度・深度」で変更できます。
UAVが水中目標の受信位置へ向かう場合は、高度を維持する設定を確認します。水中のz座標へUAVを直接下げないでください。

[操作10-03] 通信を受けて観測位置へ向かう
1. 観測側にセンサーを設定します。
2. 観測側の対象探知から「報告」へ遷移させ、報告先を移動するユニットにします。
3. 移動側の目的地を「受信した目標位置」にします。
4. 移動側に「情報受信」イベントノードを作り、「目的に向かって進む」へ接続します。
5. 最初の報告位置へ一度だけ進むなら発火回数は一度だけ、報告ごとに移動先を更新するなら繰り返しにします。
6. 到着後を測りたい場合は、移動から「到着」で別の状態へつなぎ、その状態を計測します。

位置情報が届くまで受信位置への移動は待機します。通信の受信自体は位置情報なしでも起き得ます。新しい報告が保存されただけでは、移動中の固定目標は変わりません。受信イベントでその移動状態へ再入場させます。
中継でも観測位置・観測時刻・元の観測者を保持します。中継時刻を新しい観測時刻にはしません。同じ目標の古い報告で新しい受信位置を上書きしません。

[操作10-04] Xmまで近づいたら遷移させる
遷移線またはイベントノードで「指定距離まで近づく」を選び、目的・距離（m）・距離の種類を設定します。
水平距離はx/yだけ、絶対距離は高度差も含む3次元直線距離です。UAVが水中目標の真上へ来ても、絶対距離では高度差が残ります。
この条件はセンサーで探知できたかとは別です。状態に入った時点ですでに範囲内なら直ちに成立します。繰り返しイベントは範囲外へ出て再び入る必要があります。
目的に向かう移動と経路への途中合流は、地形を自動回避しません。第07章で作る固定経路の自動生成とは区別してください。

## 11 同じ挙動を担当ごとに使い分ける

[操作11-01] 経路・目的・数値を担当時に指定する
1. 挙動の状態・条件の編集欄で、設定したい項目の指定方法から「＋ 担当時に指定する値を作る」を選びます。
2. 「巡回経路」「待機時間」などの名前を付け、種類・単位を確認します。
3. 必要なら「挙動に既定値を設定する」を使い、通常の値を設定して保存します。
4. 「担当・共有設定」の「この担当で使う値」で、そのタスクの具体的な経路・地点・数値を設定します。
5. 別のタスクで同じ挙動を選び、違う担当値を設定します。
6. 「適用」で確定します。

対応項目は経路、移動・接近の目的、報告先の単体、待機秒数、巡回速度比、時間イベントの秒数、接近距離です。距離の種類、センサー使用、経路への入り方、発火回数は図側の直接設定です。
「担当時に指定する値」ボタンから名前・既定値を編集できます。既定値を使うか上書きするかは担当側で選びます。必要な値が未指定の場合は適用できません。
名前付き経路・目的地そのものを編集すると、それを参照する担当へ共通して反映されます。担当値を使っていても、同じ経路を選んでいれば独立した経路のコピーではありません。
同じタスクで使用する挙動を別の挙動へ変更すると、以前の担当値は整理されます。必要な値を設定し直してください。

## 12 計算・記録・再生

[操作12-01] 計算する
1. 地図下の「計算設定・乱数シード」を開きます。
2. 終了時刻（分）、シード、試行番号、計算刻み（秒）、通常の記録間隔（秒）を確認します。
3. 「計算」を押し、終了時刻までの計算が完了するのを待ちます。
4. 「記録済み」になったら、再生・時刻スライダー・履歴で確認します。
5. 必要なら「記録保存」で保存します。

「計算中止」は処理を止める操作です。正常完了とは別で、計算済みの結果として扱いません。編集すると以前の記録は無効になり、「未計算」へ戻ります。
探知は計算刻みを使います。通信の到着、待機終了、目的への到着などは、刻みの途中の時刻でも処理します。通常の記録間隔だけで全てのイベント時刻を丸めるものではありません。

[設定12-02] 刻み・記録間隔・乱数
| 設定 | 役割 |
|---|---|
| 計算刻み | 探知・動く目的への追従などの判定の細かさ |
| 通常の記録間隔 | 再生記録の基本の保存間隔。細かいほどメモリが増える |
| シード・試行番号 | 乱数の結果を再現する識別 |
| 次の試行 | 別の試行番号で確認する |

記録間隔は計算刻み以上で、その整数倍にします。状態・動きが変わる時刻などは追加で記録されるため、実際のフレーム数は通常間隔だけから計算した数より増えることがあります。
同じ定義・シード・試行番号・計算設定で再現します。刻みを変えた結果を、必ず以前と同じ結果になるものとして扱いません。短い接触や曲がる移動目標は、刻みを細かくした結果とも比較します。

[操作12-03] 再生する・巻き戻す
「▶ 再生」で再生し、同じボタンで一時停止します。速度倍率を変えると表示の進み方だけが変わります。
「＋60秒」、時刻スライダー、「↺ 開始位置」で記録内の時刻を移動できます。巻き戻しによる再計算はありません。
再生中の設定を変更した場合は、新しい設定の計算を行ってから再生します。画面の初期配置と、その計算試行での経路上の出発位置が異なる設定もあります。

## 13 状態到達の計測・モンテカルロ分析

[操作13-01] 到着後の状態へ入ったことを測る
1. 挙動を、移動状態から「到着」で次の「終了」または「情報を待つ」状態へ移る構成にします。
2. 次の状態を選び、「この状態を計測対象にする」を押します。右クリックの「計測対象にする」でも設定できます。
3. 最後に挙動の「適用」で確定します。
4. 地図上部で「配置編集」「地形・領域編集」と並ぶ「分析」を押します。
5. 「この計測条件を使用」を確認し、「計測する結果」を「挙動の状態への初回到達」にします。
6. 「対象タスク」「到達を計測する状態」を確認します。
7. 成立条件と期限（開始から分）を指定します。

| 成立条件 | 数える時刻 |
|---|---|
| 担当のうち一つ | 最初の担当が指定状態へ入った時刻 |
| 有効な担当すべて | 最後の担当が初めて指定状態へ入った時刻 |
| 指定数の担当 | 必要な人数がそろった時刻 |

群は生成された個体ごとに数え、無効な担当は除外します。0個の場合は「すべて」でも成立にしません。初期状態を対象にすると時刻0で到達します。状態の処理を終えたかではなく、その状態へ入ったかを測ります。
一度その状態から出て再び入っても、初回の到達時刻を使います。期限後の到達は期限内到達数へ含めません。タスク・対象状態を削除、またはタスクの挙動を変更すると、計測条件が解除される場合があります。

[操作13-02] UUV数と探知距離を比較する
1. 計測条件を設定したシナリオで「分析」を開きます。
2. 「比較変数を追加」を押します。
3. 対象にUUV群、属性に群の個数を選び、比較値へ例えば「4, 8, 16」を入力します。
4. もう一つ追加し、同じ群の「最大探知距離」を選びます。km表示なら「0.75, 1.5, 2.5」を入力します。
5. 各条件の試行数を設定します。3値×3値なら9条件です。
6. 必要なら「ばらつきを追加」で対象・属性・一様分布または三角分布を指定します。
7. 計画表示の条件数・試行数を確認し、「分析を実行」を押します。
8. 完了後に比較結果を確認します。

比較変数は固定した複数値の全組合せです。試行ごとのばらつきは、各試行で指定分布から値を抽出します。同じ対象・属性を重複して両方へ指定しません。
分析の属性欄には、その対象で意味のある項目が表示されます。共有経路で使われない個別配置値などは候補から外れる場合があります。表示単位を確認してください。通常のユニット速度はkm/hですが、分析の「移動速度」はm/sです。
「判定間隔」は通常計算・記録と共通の計算刻みです。この欄を変更すると通常の記録間隔も同じ値へ設定されます。

[結果13-03] 分析結果を読む・再現する
・成立率／成功率は、指定した計測条件が期限内に成立した試行の割合です。
・未成立率は条件が成立しなかった割合です。未検知率と呼べるのは探知を計測条件にした場合です。
・95%信頼区間は、試行数に対する推定の幅です。現実の任務成功を保証する区間ではありません。
・成功時刻の中央値は成功した試行だけを集計します。失敗試行を遅い時刻として入れた中央値ではありません。
・状態到達の時刻分布は、全試行を分母とする累積到達率です。未到達の試行も分母に残ります。
・要求成功率は比較の目安です。要求率を変えてもセンサー性能や判定を自動改善しません。
・横軸は比較する属性を選び、線形／対数を切り替えます。0個は対数図から除外されても表には残ります。

結果の条件行で試行番号を選び「再現」を押すと、その試行を計算・記録して地図で確認できます。分析全体の詳細位置記録を保存するものではありません。
再現後に「分析元のシナリオに戻す」で元の定義へ戻せます。分析結果を残すには「結果を.txtで保存」を使います。

## 14 やりたいこと別の操作例

[例14-01] 航路Aを進み、敵を探知したら航路Bへ進む
1. 名前付き経路として航路Aと航路Bを作ります。両方とも検査します。
2. 「経路を進む」の状態を二つ作り、それぞれ航路A・航路Bを選びます。
3. Aの状態を初期状態にします。
4. AからBへ線をつなぎ、線の条件を「対象を探知」にします。
5. 観測側のセンサー能力とAの状態中のセンサー使用を有効にします。
6. Bの「経路への入り方」を最初から／最短地点からの意図に合わせて選びます。
7. 適用して計算し、切替時の直線合流が島を横切らないか確認します。
どの状態からでも切り替えたい場合は、線の代わりに共通の「対象探知」イベントノードからBへ接続します。

[例14-02] 通信で受け取った位置へUAVを向かわせる
第10章の操作10-03を使います。目的は「受信した目標位置」、高度は「移動開始時の高度・深度を維持する」です。最初の報告だけなら情報受信は一度だけ、報告ごとに修正するなら繰り返しです。
「ユニットの現在位置」を目的にすると報告一回の観測位置への移動ではなくなるので、区別してください。

[例14-03] ひな型単体を使わずUUV群だけ計算する
単体を設定して群を作り、元の単体の「計算に使用する」を外します。群はそのまま有効です。計測タスクの担当には実行する群を指定します。

[例14-04] 島を避ける潜水艦経路を作る
「島を避ける経路の自動生成」サンプルを開くと、読込時に深度100m・追加余裕20mの迂回経路ができます。対象ユニットの経路の検査・自動生成で必須地点や深度を変え、保存して検査・計算します。
地形の海面が0mの場合、生成画面のz座標は-100、ユニット設定の深度表示は100です。

[例14-05] 帰投した担当数を測る
帰投地点を地点目的地にし、移動状態から「到着」で終了状態へ遷移させます。その終了状態への初回到達を計測し、タスク・必要人数・期限を選びます。帰投を命じた移動状態そのものを計測すると、命令開始を数えてしまいます。

## 16 困ったときのFAQ

[FAQ-01] 再生できない／移動しない
「未計算」ならまず「計算」を押します。設定変更後は再計算が必要です。計算済みなら、速度0、経路なし、情報待ち・時間待ち、無効化、地形制約停止、現在の状態を確認します。右側の「再生中の状態」と「計算履歴」で理由を切り分けます。

[FAQ-02] 「操作」というプルダウンがない
現行版は右クリックと対象別の編集へ移しました。地図の空白、ユニット、経由点でメニューが変わります。旧UIの手順をそのまま案内しません。

[FAQ-03] 開始ノードが作れない／どこから始まるか分からない
シーン開始ノードは廃止し、状態ノードの初期状態指定を使います。その他の開始きっかけはイベントノードです。第09章です。

[FAQ-04] 線をつないだのに適用できない
状態の種類、初期状態またはイベント、イベントの遷移先、線の条件、必要な経路・目的・担当値を確認します。線をクリックして「遷移する条件」を指定します。終了からの線は使えません。

[FAQ-05] 探知確率100%なのに探知できない
「距離0で1分の探知確率」は全距離・毎刻みで必ず探知する設定ではありません。距離減衰、対象領域・陣営、被探知係数、地形遮蔽、状態中のセンサー使用、計算刻み、ユニットの有効／無効を確認します。終了状態は探知しません。最大距離の表示球も確実に探知できる境界ではありません。

[FAQ-06] 通信確率100%、距離内なのに失敗する
「計算履歴」で送信失敗の理由を読みます。通信無効なら送信側の通信を有効化、受信先不在（無効・計算対象外）なら報告先ID・単体の有効化、通信範囲外なら送信時点の3次元距離、地形遮蔽ならその設定と経路を確認します。確率100%はこれらの成立条件を省略しません。
古い版の「受信先不在・配置不正」というまとめた表示だけでは、原因を一つに断定できません。現行版では地形制約で停止したユニットも、有効な現在位置から受信・状態遷移できる場合があります。「停止したから必ず通信不能」と案内せず、表示された詳細理由と版を確認します。

[FAQ-07] 一回の通信で相手の現在位置を追い続けている
目的が「ユニットの現在位置」になっていないか確認します。報告位置へ進む場合は「受信した目標位置」に変更します。第10章です。

[FAQ-08] 受信したのに位置へ向かわない／新しい報告位置へ変わらない
情報受信イベントの接続先、位置情報の有無、目的の種類、速度、地形エラーを確認します。位置情報がなければ待機します。報告ごとに更新するなら情報受信を繰り返しにし、その移動状態へ再入場させます。受信データが保存されるだけでは現在の固定目標は変わりません。

[FAQ-09] UAVが水中へ降りて地形制約で止まる
移動状態の「移動中の高度・深度」を、移動開始時の高度・深度を維持する設定にします。目的の本来の高さへ合わせる設定や、経路のz座標も確認します。

[FAQ-10] 島の中を通る／浅瀬で止まる
「経路を検査」で不正区間を確認し、「経路の検査・自動生成」で通れる必須地点・高度・深度・余裕から迂回経路を作ります。経路自体が安全でも、イベント時の合流や目的への直線移動、航跡のずれが地形を横切る可能性があります。履歴で停止した状態と区間を確認します。

[FAQ-11] 自動生成できない
始点・終点・全ての必須地点が通れるか、領域外でないか、深度・高度・余裕・周回3点以上を確認します。狭い海峡は探索格子で見つからないことがあります。地点・地形・設定を見直します。失敗しても前の座標は保持します。

[FAQ-12] 最短地点からを選んでも島を迂回しない
経路への入り方の「最短」は直線距離で近い合流点を選ぶ意味です。障害物を避ける経路自動生成とは別です。第07章の制約07-06です。

[FAQ-13] 到着したのに計測されない／動く前から成功になる
対象タスク・対象状態・期限・人数条件を確認します。移動状態を計測すると移動開始を数え、初期状態を計測すると時刻0を数えます。到着条件で次の状態へ移り、その次の状態を計測します。

[FAQ-14] 群の個体を編集できない／ひな型も計算されてしまう
生成個体の属性は「この群を編集」で変更します。元の単体は「計算に使用する」を外せば編集用に残せます。群の有効／無効とは独立です。

[FAQ-15] 地形編集中の右クリックでメニューが出ない
通常の右クリックは標高取得です。編集メニューはShift＋右クリックです。右ドラッグは平行移動になります。

[FAQ-16] 領域サイズを縮められない
新しい範囲外へ出る位置・経路・目的地があると止めます。表示された対象を先に移すか削除します。領域サイズは座標を比例縮小する操作ではありません。

[FAQ-17] versionは1にしてくださいと言われる／HTMLとJSの版が違う
使用ブランチ・配布版・コピーしたファイルの組合せを確認します。現行のシナリオはversion 3です。旧版のプログラムやファイル混在の可能性があるため、JSONのversionだけを書き換える対処は案内しません。持ち込み版は5ファイルを同じ版に揃えます。

[FAQ-18] Cannot set properties of null (setting 'onclick')／画面部品がありません
起動レポートをコピーし、HTML・JSの版が揃っているか確認します。ファイル欠落・古いキャッシュ・HTML改変などを切り分けるエラーです。「最新版を読み直す」が出ればそのリンクを使います。原因をWorkerだけに決めつけません。

[FAQ-19] Workerの応答がない／classicは正常、moduleは失敗
HTTPSだから必ずmodule Workerが動くわけではありません。通信・認証・配信・MIMEタイプ・環境制限・起動遅延などを確認します。「ヘルプ」→「動作環境の確認」でSimSim本体のWorkerも確認します。古い10秒の判定だけでは非対応と断定しません。現行の本体は最大60秒待ち、10秒時点は待ち表示です。
module Workerに制限がある環境にはclassic Workerを使う5ファイルの持ち込み版があります。F12を使えない場合は、画面の起動レポート、環境確認結果、ファイル構成・版を管理者へ伝えます。診断の単純なclassic Worker成功だけで本体・分析も全て正常とは断定しません。

[FAQ-20] 記録が大きい／計算や分析の上限に達する
ユニット数、終了時刻、記録間隔、計算刻み、イベント数を確認します。用途に合う範囲で減らしてください。刻みを粗くすると判定も変わり得ます。表示の高さ倍率・再生速度を変えても記録量は減りません。第17章の上限を参照します。

[FAQ-21] 保存したTXTを開いたら動作記録がない
上部の保存はシナリオ定義です。計算して再生するか、計算済み記録を残したい場合は「記録保存」を使います。分析結果も別の保存です。第03章です。

[FAQ-22] 分析ボタンが見つからない
上部のファイル操作ではなく、地図上の「配置編集」「地形・領域編集」と同じツールバーにあります。

[FAQ-23] 群の個数0を設定できない
群の作成・通常編集は1以上です。0個の対照条件は分析の「比較変数」で群の個数として指定します。0個では担当がなく、状態到達の全員条件も未成立です。

## 17 ショートカット・単位・上限

[一覧17-01] ショートカット

## 18 持ち込み版・モデルの範囲・根拠

[操作18-01] 社内へテキストコピーで持ち込む
持ち込み用ページ:
https://zero-error-no-warning.github.io/SimSim/portable/copy.html

1. 各ファイルの「表示」→「全文をコピー」で全文を取得します。
2. コピーできなければ「全文を選択」→Ctrl+Cを使います。
3. 次の5ファイルを同じフォルダへUTF-8で保存します。
   index.html / styles.css / main.js / worker.js / analysis-worker.js
4. 「TXTを保存」で取得した場合は、配信用のファイル名から末尾の.txtを外します。例えばmain.js.txtをmain.jsにします。

6. 更新時は5ファイルを同じ版へ揃えます。

持ち込み版はThree.jsと11個のサンプルを内蔵し、classic Workerを使います。src・vendor・dataの追加フォルダは不要です。copy.htmlは持ち込み補助なので、実行用5ファイルに含みません。
通常版はsrc・vendor・dataを含む構成を保持して配信します。通常版と5ファイル版を混ぜた構成にしません。JSをJavaScript、CSSをtext/cssのMIMEタイプで配信する必要があります。管理者への依頼事項として伝えます。
この操作マニュアルは参照資料です。実行用の6番目のファイルとして必要になるものではありません。

[制約18-02] 計算モデルが扱うこと
地上・水上・水中・空中の位置と移動、格子地形、直線の地形遮蔽、距離・確率による探知、通信、条件付きの状態遷移、状態到達などの計測、モンテカルロ比較を扱います。
地形条件は、地上は陸上、水上は水深5m以上、水中は海面下1m以上かつ海底から5m以上、空中は地表・海面から10mより高い位置です。経路生成ではこれに指定余裕を加えます。水中でも見た目が海なら全深度を通れるわけではありません。
固定経路の検査は補間地形の線分内の極値も確認します。実行時の移動や直線見通しは分割した近似判定を使います。地形の表示メッシュと判定に使う格子補間の細部は同一ではありません。
燃料・充電・補給・攻撃・損耗・実ソナー伝搬、動的な障害物回避、継続追尾品質の詳細は未実装です。状態名や能力値を追加しただけで、これらの計算が追加されるものではありません。
本ツールの成功率は設定した簡易モデルと仮定の下の結果です。実装の確認結果と現実の装備性能の検証を区別します。

## 19 回答エージェント用の指示文と確認質問

[エージェント19-01] 指示欄へ設定する文案

あなたはSimSimの操作案内担当です。知識にある「SimSim 操作マニュアル」の対象UIビルドに沿って、日本語で人が画面を操作できるよう回答してください。

回答の原則:
1. 利用者の目的に対して、まず押す場所と短い操作手順を示してください。必要なら設定後に期待する表示を添えてください。
2. 画面上のラベルをそのまま使い、メニューやボタンの場所を示してください。存在しない項目、旧版のUI名を作らないでください。
3. 回答末尾に「参照: 操作07-04、FAQ-11」のように本書の章・操作・FAQ番号を付けてください。別の根拠を確認していない場合、外部サイトの検証済みとは述べないでください。
4. 人向けの質問へJSONを先に出さず、画面操作で答えてください。シナリオ生成を求められた場合は別のLLM向け生成マニュアルが必要であることを案内してください。
5. 単体と群、タスクと挙動、状態とイベント、経路と目的地、計算と再生、シナリオ保存と記録保存を区別してください。
6. 未確認の環境原因や未実装の機能は断定しないでください。資料にない機能は、可能だと推測して手順を作らないでください。
7. エラー時は本書の対応FAQを使い、エラー全文、通常版か5ファイル版か、版情報、操作対象など、切り分けに必要な不足情報だけ確認してください。スクリーンショットやF12を必須としないでください。
8. 通信100%や安全な経路という設定だけで必ず成功すると断定しないでください。地形・有効／無効・報告先・合流区間などの成立条件を確認してください。
9. versionの数字だけを変更して読込エラーを回避する案内はしないでください。異なる配布版・ファイル種類・キャッシュを確認してください。
10. 各設定欄の単位を明記してください。特に深度表示の正の値と絶対z座標の負の値、速度のkm/hと分析のm/sを取り違えないでください。
11. 設定を変えた操作では、必要な「適用」「保存」「再計算」を案内してください。挙動の下位画面での保存だけを最終確定とは扱わないでください。
12. ツールを操作していない限り、設定変更・計算・保存を実行したと述べないでください。利用者へ案内する役割です。

## 20 複数計測点・段階別分析・計算履歴・一覧との連動

[操作20-01] 複数の段階を計測する
1. 地図上部の「分析」を開く。
2. 「追加の計測点・段階別分析」を開き、「＋ 計測点」を押す。
3. 計測点名、タスク、状態、到達条件（一つ／全員／指定人数）、期限（秒）を指定する。最大12点。
4. 段階間の所要時間を測る点は「所要時間の起点」に先に登録した計測点を選ぶ。シーン開始も指定できる。
5. 「分析を実行」を押す。右側の「段階別の到達率・所要時間」で比較条件を選ぶ。
設定変更は即時反映。シナリオを保存し、通常の再生も更新する場合は計算する。これらの点は、上部のミッション全体の成立条件とは独立している。追加点がある分析は、主ミッションの期限以降も終了時刻まで計算する。

[操作20-02] 表の読み方と未達を再生する
「到達／全試行」「到達率」は全試行を分母とする。「成立時刻の中央値」は期限内に条件が成立した試行のみ。所要時間は起点と終点が成立し、終点が起点以降の試行のみで集計する。「起点成立後の到達」は起点成立試行を分母とする。順序逆転の試行は所要時間から除外し、件数を表示する。
人数条件の成立時刻どうしの差であり、同じ個体の移動時間とは限らない。初期状態への到達は時刻0。瞬時に通過する報告状態も計測できる。
未達試行の番号を選び「未達を再生」を押す。同じシード・試行番号・抽出値で記録を作成し、当該計測点の期限へ移動する。再生中の条件と未達計測点名を地図下に表示する。
分析結果のTXTには計測点ごとの結果も含まれる。再読込で集計を表示できる。記録保存にも各計測点の結果を含む。

[操作20-03] タイムラインから経過を調べる
計算完了後、地図下の「計算履歴」を押す。全期間のユニット別タイムラインが表示される。上段の帯は挙動の状態、下段の点は探知・送信・受信・送信失敗・到着など、白線は再生時刻。
帯や空白をクリックするとその時刻へ移動。点をクリックすると、そのイベントの時刻とユニットへ移動する。点はTabとEnterでも操作できる。ダイアログを閉じると地図を確認できる。
一覧は先頭30個まで。「タイムラインのユニット」で個体を指定すると、残りの個体も確認できる。過密な点は同じ種類・同じ表示位置でまとめる。全件のデータは保持する。
「現在時刻までのイベント一覧」を開くと従来の詳細テキスト（末尾200件）を確認できる。時刻を巻き戻してもタイムラインの全期間履歴は消えない。記録読込でも表示される。時刻移動は再計算しない。

[操作20-04] 一覧と3D表示を対応させる
画面は左から「タスク一覧 | ユニット一覧 | 3D表示 | ユニット編集」の4ペインです。名前と現在状態はユニット一覧に表示します。3D表示・真上表示に重複した名前ラベルは表示しません。
タスク名をクリックすると、担当ユニットを一覧の水色の帯と地図の水色の輪で強調します。ほかのユニットも引き続き選択できます。「編集」でタスクの設定画面を開きます。
ユニットを選ぶと一覧・地図・右側の編集対象がそろい、担当タスクも強調します。地図で選択した場合は一覧の対象行までスクロールします。検索条件に一致しない選択中ユニットも表示します。
一覧にマウスを置くかキーボードでフォーカスすると、対応する地図の記号を水色の輪で強調します。選択中・フォーカス中の行から地図の記号へ対応線を表示します。行と記号が表示範囲にある場合に表示します。「表示」→「一覧との対応線」で切り替えます。
各ペインの境界をドラッグすると幅を変更できます。境界にキーボードでフォーカスして左右矢印キーでも変更できます。タスク一覧の「‹」で折りたたみ、「›」で再表示します。幅と折りたたみ状態は同じブラウザに保存します。

[操作20-05] サンプルと制約
「サンプルを開く…」→「段階別計測・通信履歴」で試せる。中継の通信成功確率を0・50・100%で比較し、報告開始・中継開始・UAV移動開始・到着の各点を測る。
追加計測点は状態への初回到達のみ。地理的な計測線、追尾継続時間、個体ごとの段階間時間、感度分析のランキング、配置・経路・挙動をまとめた運用案の比較は未実装。
回答エージェントは、追加計測点とミッション全体の成立条件を混同しないこと。単位は追加点の期限が秒、主ミッションの期限が分。
